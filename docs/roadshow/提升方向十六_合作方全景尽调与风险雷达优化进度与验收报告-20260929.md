## 二、与已有方向的融合方式

### 2.1 与方向五“企业能力护照”的关系

方向五继续回答“我方是否满足招标要求”。方向十六回答“外部合作方是否值得合作、还要调查什么”。两者没有混用数据：

- 我方能力、资质、产品、案例仍进入企业能力护照；
- 外部客户、供应商、代理机构、联合体伙伴的信用、关系和合作事实进入合作方尽调；
- 页面文案和 API 返回中明确写出这条边界；
- 外部合作方材料不会自动成为我方能力证明；我方资质也不会被当成合作方信用证据。

这种隔离避免了比赛演示中最容易出现的逻辑错误：把“我们有能力投标”和“对方适合合作”混为同一判断。

### 2.2 与方向十一“跨来源可信关系图”的关系

方向十六沿用了方向十一的三项语言体系：

1. 所有事实结论引用稳定证据 ID；
2. 图中的关系明确分为事实、推断、人工确认；
3. 状态统一使用已核验、待复核、缺失、失效、已撤回等业务语言。

方向十一解决公告、版本、附件、结果之间的关系；方向十六将同一套可审计语法扩展到企业、人员、项目、采购人、合作方、竞争者和联合体伙伴。两张图保持边界，避免把“公告相关”误写成“企业存在股权或控制关系”。

### 2.3 组合后的比赛表达

完整表达链路变为：

> 机会来自可信公告 → 公告及附件通过证据链核验 → 我方能力护照逐项匹配 → 外部合作方通过全景尽调 → 风险问题进入飞书任务 → 人工负责人作出有期限的合作结论。

这条链路把“发现机会、判断能否投、判断与谁合作、把问题交给谁、何时复核”连成一个闭环。

## 三、十个实施步骤及逐项验收

### 3.1 第一步：数据对象与工作区隔离

已建立以下数据对象：

- `company_entities`：企业/机构/个人主体；
- `company_aliases`：法定名称、历史名称和别名；
- `company_evidence`：企业证据、许可、访问规则和快照；
- `company_risk_signals`：风险、事实、缺失三类信号；
- `company_relationships`：事实、推断和人工关系；
- `due_diligence_reviews`：人工合作结论及有效期；
- `company_due_diligence_tasks`：法务、财务、销售、交付和核验任务；
- `company_change_subscriptions`：主体变化订阅；
- `company_due_diligence_snapshots`：可离线打开的画像快照；
- `company_due_diligence_audit_events`：敏感访问和关键操作审计；
- `company_due_diligence_answers`：证据追问及引用结果。

所有业务对象均带 `workspace_id`。统一社会信用代码只在同一工作区内唯一，支持不同事业部各自维护同一外部主体，同时防止单个空间重复建档。

### 3.2 第二步：企业主体消歧

消歧规则已经固化：

- 统一社会信用代码精确匹配时，可以唯一确认；
- 企业名称、别名、地区、法定代表人只参与候选排序；
- 两个同名主体会保留为两个候选，不自动合并；
- 只有空间负责人或系统管理员可以确认主体；
- 确认操作保存人员、时间、原因和信用代码后四位审计信息。

测试覆盖同名不同地区、同名不同法定代表人、信用代码冲突、普通成员越权、跨工作区访问等情形。

### 3.3 第三步：聚合已有数据

第一阶段只使用 TenderTrace 已经合法持有的数据：

- 真实采购公告和合同公告；
- 已记录的中标/成交结果和历史供应商；
- 机会客户干系人；
- 客户关系动作及结果；
- 组织记忆；
- 已归档投标记忆和授权上传材料。

聚合时不只保存摘要，还保存来源类型、原链接、发生时间、公告 ID、主体匹配依据和内容哈希。关系材料和组织内部材料自动进入敏感访问范围。

### 3.4 第四步：拆分风险解释链

每条风险包含：

| 字段 | 作用 |
|---|---|
| 事实信号 | 证据原文中可以直接核验的事实 |
| 风险解释 | 该事实为什么值得关注 |
| 业务影响 | 对准入、签约、履约、付款、交付或品牌的可能影响 |
| 尽调问题 | 签约前需要让对方或内部责任人回答的问题 |
| 缓释措施 | 可落入合同、审批或交付计划的控制措施 |

系统不输出胜率，也不输出单一综合风险分。六个维度分别显示覆盖、风险和缺失状态，允许负责人看到判断的具体依据。

### 3.5 第五步：外部数据合规边界

外部证据只允许四种接入类型：官方 API、授权接口、官方公开快照、人工上传。每条记录必须保存：

- 来源许可或授权编号；
- HTTPS 原地址；
- 访问策略；
- 访问频率；
- 采集时间；
- 内容 SHA-256 快照；
- 主体匹配依据；
- 有效期和置信度。

未授权浏览器抓取、突破访问频率、复用未授权登录态和绕过验证码会被拒绝。无法合法稳定获取的数据只允许人工上传或授权接口接入。

### 3.6 第六步：官方主体核验

官方核验必须满足全部条件：

1. 证据来自官方 API 或官方公开快照；
2. 来源许可已填写；
3. 统一社会信用代码出现在证据快照正文；
4. 代码与确认值完全一致；
5. 操作者是空间负责人或系统管理员。

任何代码不一致、证据类型不合规或权限不足都会阻止确认。

### 3.7 第七步：证据和风险有效性

证据状态包括待复核、已核验、已过期、已撤回、主体不匹配和已驳回。风险信号包括有效、待复核、需补证、已失效和已忽略。

当证据超过有效期或被撤回时，关联风险立即失去“确定性”标记。人工确认的风险不会被后续自动评估覆盖，但其底层证据失效后会强制进入需复核或失效状态。

### 3.8 第八步：证据追问

追问接口支持“如果合作，合同里最需要约束什么”等业务问题。返回内容包含：

- 当前最高优先级风险；
- 每条风险的企业证据 ID；
- 尚未覆盖的信息；
- 最坏业务影响；
- 合同或流程缓释措施；
- “仅基于当前工作区证据”的范围说明。

如果没有已核验负面证据，系统会明确回答“当前没有已核验的负面风险证据；这不等于无风险”，不会把空数据说成“企业安全”。

### 3.9 第九步：飞书尽调任务

任务支持法务、财务、销售、交付和通用核验五类责任域。每个任务包含问题、负责人、截止时间、关联风险和关联项目。

飞书同步使用稳定幂等令牌。首次同步创建任务，重复同步复用同一任务。系统保存：

- 飞书任务 GUID；
- 当前飞书任务状态；
- 同步时间；
- 失败信息；
- 飞书返回的完整回执。

### 3.10 第十步：敏感材料隔离与审计

敏感证据必须保存脱敏副本。普通成员看到脱敏内容；负责人和系统管理员可以查看原文。跨工作区读取会返回不存在或无权限，不会泄露主体是否存在。

每次敏感材料访问都会记录：工作区、企业主体、证据 ID、访问人员、访问时间，以及本次显示原文还是脱敏副本。

## 四、最终产品界面

新增主导航“合作方尽调”，页面由五部分组成：

1. 合作方主体目录：按名称搜索、建立主体档案、显示消歧状态；
2. 顶部总览：主体核验、合作建议、风险等级、证据完整度、人工复核；
3. 六维画像：主体与股权、经营与信用、司法与合规、历史项目与履约、关系与冲突、舆情与外部事件；
4. 风险和证据：五段式风险卡、证据账本、关系图、飞书任务回执；
5. 决策区：证据追问、人工合作结论、有效期和前置条件。

界面支持桌面投屏和窄屏：1040 像素以下切换为单列主体目录和画像，720 像素以下将六维卡片、风险说明和表单进一步改为单列，避免横向溢出。

## 五、真实演示案例

### 5.1 演示主体

真实来源项目为“成都市自然资源调查利用研究院（成都市卫星应用技术中心）机架式服务器直接选定采购合同”。TenderTrace 已固化的公开公告正文显示成交供应商为“成都华东电脑系统集成有限公司”。

系统从本地真实公告识别该供应商并建立画像。除此之外，本次加入的合作访谈材料明确标注为“路演演示用脱敏材料，不代表对真实企业的事实判断”，不会被误作真实企业处罚、司法或舆情事实。

### 5.2 演示步骤

1. 打开“合作方尽调”；
2. 选择“TT 项目组群”；
3. 打开“成都华东电脑系统集成有限公司”；
4. 查看真实服务器采购公告对应的项目与履约证据；
5. 查看六维画像，主体、司法、关系和舆情显示为待补证；
6. 提问“如果合作，合同里最需要约束什么？”；
7. 系统回答当前没有已核验负面风险，同时列出四个缺口和合同前置条件；
8. 查看“有条件合作”人工结论和两项条件；
9. 查看两项飞书任务及 GUID 回执；
10. 保存或打开已核验离线快照。

### 5.3 演示结论

当前结论为“有条件合作”，不是“无风险合作”。理由是：真实历史项目事实和脱敏合作材料可核验，但主体代码、司法合规、关系冲突和近期舆情仍需补齐。结论有效至 2027-03-28，后续自动运行不能覆盖该人工结论。

- 飞书原有消息、日历、多维表格和任务能力保持可用。

### 9.2 受控共享

方向十六只共享组织工作区、公告 ID、证据 ID 和飞书客户端，不直接改写方向五或方向十一的数据。共享发生在接口和展示层，而不是把不同业务对象强行合并到同一张表。

### 9.3 性能边界

第一阶段聚合会扫描最多 1000 条本地公告，当前 57 条公告下响应很快。数据量达到数十万条时，应增加企业名称倒排索引或实体链接队列；当前比赛和本地部署规模不需要提前引入复杂基础设施。

## 十、目前真实边界和风险

以下部分如实保留，不将“未接入”描述成“已完成”：

1. 工商、司法、处罚、制裁和舆情的外部生产接口尚未购买或授权；当前系统已准备合法接口和人工上传通道；
2. 真实演示企业没有在本地保存官方统一社会信用代码，因此主体维度保持待确认；
3. 关系图已支持事实、推断、人工关系，但第一阶段没有自动推断股权穿透；
4. 变更订阅已经保存订阅范围，外部源接入后才能产生真实主体变化事件；
5. 浏览器自动验收工具本次不可用，但页面本身、API、JS 和响应式布局已通过其他可复现检查；
6. 全仓库 Ruff 历史问题仍存在于旧文件和临时报告脚本，不属于本方向回归故障。

这些边界不会阻塞本方向的核心演示。相反，页面会把未覆盖项明确展示出来，符合“证据不足不下确定结论”的产品原则。

## 十三、最终验收结论

方向十六已经达到“能跑、能展示、能解释、能审计、能协作”的比赛版本标准。真实历史项目可以进入企业画像；风险结论可以回到证据；缺失信息不会被误判成负面；人工合作结论有人员、时间、原因和有效期；飞书任务有真实回执；离线时可打开最近核验快照；全量回归证明没有造成原有功能损失。

建议将方向十六作为全国总决赛演示中的第二个“惊艳点”：先用可信关系图说明项目证据可靠，再用合作方风险雷达说明 TenderTrace 不只告诉团队“哪里有标”，还帮助团队回答“该和谁合作、签约前必须问什么、由谁在什么时间完成核验”。
