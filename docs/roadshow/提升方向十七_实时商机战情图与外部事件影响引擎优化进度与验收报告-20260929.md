## 一、执行结论

## 二、与已有方向的融合和边界

### 2.1 与方向十“全国与全球机会雷达”的关系

方向十回答“哪些地区存在机会、哪些来源健康、覆盖是否可信”。方向十七回答“具体事件何时发生、交易从哪里流向哪里、外部事件可能影响哪些项目”。

- 复用方向十的真实公告、地区、品类和数据源可信度；
- 新增具体事件、成交连线、时间轴、动态聚合和外部事件；
- 地图数量与列表使用同一查询结果，避免两个页面各自计算导致口径不一致；
- 点击商机仍回到项目和原始证据，不在地图页另造一套机会判断。

### 2.2 与方向三“变更影响引擎”的关系

方向三处理公告版本变化对要求、任务和投标决策的影响。方向十七把影响机制扩展到外部空间事件，但继续遵守同一原则：事实和推断分开。

- 外部事件是权威来源中的事实；
- 项目影响是规则关联候选；
- 候选说明匹配依据、影响范围、置信度、建议动作和待确认事项；
- 人工确认前不修改项目、机会、尽调或投标结论；
- 确认、驳回和持续观察均保存人员、时间和备注。

### 2.3 与方向十六“合作方全景尽调”的关系

战情图能够把外部事件候选关联到项目、产品或合作方，但合作风险结论继续由尽调驾驶舱承担。地图负责发现异常和建立全局感，尽调负责验证企业事实和作出有期限的人工结论。

完整业务链路变为：

> 机会雷达发现地区机会 → 战情图观察事件和交易流 → 点击进入真实公告 → 变更引擎分析公告冲击 → 尽调核验合作方 → 飞书战情室分派行动。

## 三、十个实施步骤及逐项验收

### 3.1 第一步：建立独立事件数据模型

数据库版本升级到 57，新增五类对象：

| 对象 | 用途 |
|---|---|
| `geo_events` | 标准化商机与成交事件 |
| `business_flows` | 已有证据支持的采购方到供应方流向 |
| `external_events` | 权威外部事件及原始来源 |
| `impact_links` | 外部事件与项目/产品/合作方之间的候选关系 |
| `map_replay_frames` | 经核验的地图离线回放帧 |

每类事件保存来源、事件时间、采集时间、证据状态、坐标精度和空间范围。外部事件额外保存来源许可、访问策略、访问频率和内容 SHA-256 快照。五张表均建立按时间、事件、复核状态或回放范围使用的索引。

### 3.2 第二步：标准化真实业务事件和地理位置

系统从现有公告中识别机会、成交、采购人、供应商、金额、品类和地区，生成统一事件。当前本地真实数据标准化出 45 个业务地理事件，其中 18 个成交事件。

定位规则遵守三条边界：

1. 国内公告优先定位到省或可验证城市；
2. 国际公告可以只定位到国家；
3. 无法支持更高精度时明确显示“省级”或“国家级”，不伪造具体经纬度。

本次自动验收中，国内有效事件可定位率为 100%，主案例省级精度为 100%。另有 2 条国际业务事件只到国家级，页面会显示其精度，不将国家中心点描述成项目的精确地址。

### 3.3 第三步：建立统一事件接口

后端统一返回商机、成交、流向、外部事件、影响卡、聚合簇、时间轴、图例、来源规则和回放状态。前端不直接抓取外部网站，不在浏览器临时拼接业务数据。

同一个 API 同时驱动地图与无障碍事件列表，因此地图点数、筛选条件和列表口径一致。主题、范围、时间窗口和图层开关都进入同一个查询上下文。

### 3.4 第四步：实现本地优先的中国/全球地图

页面支持中国和全球一键切换，并使用本地可运行的示意边界与标准化坐标。当前实现不依赖在线地图 SDK，因此在网络波动或比赛现场没有第三方底图配额时仍可打开。

中国视图只显示国内业务事件和中国境内外部事件；全球视图显示全部可用国家。服务器主题当前中国视图有 20 个事件：9 个商机、7 个成交、1 条业务流、4 个外部事件，共 11 个聚合簇。

### 3.5 第五步：建立可解释的业务流与影响映射

业务流只有采购地和供应方地点都能由已有证据支持时才生成。当前真实流向来自成都市自然资源调查利用研究院服务器采购合同，采购地为四川省，供应商为成都华东电脑系统集成有限公司，合同金额口径为 88,000 元。

外部影响第一版使用保守地区规则：同一国家或在事件影响半径内才生成候选。每条候选展示：

- 事件国家和目标国家；
- 规则键和匹配种类；
- 受影响地区与产品类别；
- 置信度；
- 仍需核验的交付地点、合作方所在地和运输路径；
- 不修改原项目结论的边界说明。

### 3.6 第六步：影响候选与人工复核

影响关系支持待复核、已确认、已驳回和持续观察。系统可以给出候选解释和建议动作，但不能独立宣布项目已经受影响。

人工复核会保存复核人、复核时间和备注。已确认结果仍可打开原事件、目标项目、规则和快照证据；驳回结果不会被下一次自动同步悄悄覆盖为确认。

### 3.7 第七步：实时推送与分级更新

本地事件变化通过 Server-Sent Events 推送修订号。浏览器建立连接后立即收到当前修订，连接期间每 10 秒发送心跳，60 秒后由浏览器自动重连。验收口径要求本地新增事件 5 秒内可见，当前实现为事件写入后立即更新修订并推送。

外部数据没有被包装成毫秒级实时。USGS 官方数据只在用户明确点击“同步 USGS 官方事件”时拉取，页面同时显示事件时间、来源生成时间和本地采集时间。这样既保留现场更新能力，又避免比赛页面静默访问外部网络。

### 3.8 第八步：控制动效、聚合和可读性

四类图层使用不同视觉语义：商机脉冲、成交菱形、业务流弧线、外部事件范围。高频同区事件按空间网格聚合为计数，减少同屏闪烁。

页面支持关闭动效，系统也遵守 `prefers-reduced-motion`。关闭动效后，事件列表、证据、下钻和筛选仍完整可用。布局为 1440×900 和 1920×1080 大屏设计，并提供 1180、820 和 520 像素响应式断点。

### 3.9 第九步：可信快照与离线回放

系统可以保存当前查询的回放帧，记录范围、时间窗口、品类、事件数据、数据时间、核验时间和状态哈希。本次生成两份经核验回放：

| 回放 | 回放 ID | 状态哈希前缀 |
|---|---|---|
| 全球服务器主题 | `ba3ac11bd2c957155225a660` | `df39b7ec93b07c7b` |
| 中国服务器主题 | `d451f590454ec7ef97e09a9c` | `6f987d7d4b085b71` |

回放模式在页面顶部清楚显示“REPLAY”、数据时间和核验时间，与“LIVE”实时模式颜色和文案不同。断网回放不会被称为当前实时数据。

### 3.10 第十步：列表、键盘和演示模式

战情图提供与地图相同查询结果的事件列表，地图点和连线使用可点击按钮，证据弹窗支持键盘关闭。用户可单独关闭商机、成交、流向或外部事件图层，也可关闭动效。

演示模式隐藏普通页面顶部区域，放大地图与影响面板，适配 1440×900 和 1920×1080 投屏。该模式只改变布局，不改变数据、证据或判断结果。

## 六、外部数据源选择与合规说明

### 6.1 已接入来源

第一版选择 USGS Earthquake GeoJSON Feed。官方文档将 GeoJSON Feed 定义为可供程序访问的地震数据接口，并说明相应实时数据流按分钟更新。TenderTrace 当前使用近 30 天 M4.5+ 官方地址：

`https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/4.5_month.geojson`

系统保存官方事件链接、事件时间、经纬度、震级、来源名称、访问策略、访问频率、采集时间和完整内容 SHA-256。USGS 数据按其版权与署名政策标记为公共领域来源，演示报告仍保留来源名称和原始链接。

### 6.2 未接入来源及原因

方案曾把联合国 OCHA ReliefWeb 列为可评估候选。2025-11-01 起，ReliefWeb API 要求使用预先批准的 `appname`。当前项目没有把未获批准的应用名写入生产代码，因此本方向没有把 ReliefWeb 宣称为已接入。

国内气象、地震、应急、口岸、关税和贸易政策来源也没有被虚构为可用。后续只有在许可、访问频率、字段稳定性和比赛演示范围完成逐源验证后才进入正式来源清单。

### 6.3 “实时”的准确口径

- 本地事件：写入后通过 SSE 分钟内、目标 5 秒内显示；
- USGS：官方流本身按分钟更新，TenderTrace 仅在明确同步时抓取；
- 低频或受限来源：显示最近成功时间，按许可频率更新；
- 断网：使用带时间、核验状态和哈希的真实回放。

## 七、API 与数据链路

主要 API：

- `GET /api/battle-map`：按范围、时间、品类和图层构建战情图；
- `POST /api/battle-map/sync`：刷新本地业务事件，可显式选择同步外部事件；
- `GET /api/battle-map/events/{event_id}`：打开事件、流向或外部事件证据；
- `POST /api/battle-map/external-events/{event_id}/evaluate`：生成规则影响候选；
- `POST /api/battle-map/impacts/{impact_id}/review`：确认、驳回或持续观察；
- `POST /api/battle-map/replays`：保存经核验地图回放；
- `GET /api/battle-map/stream`：接收本地修订和心跳。

数据链路：

> 已有公告/结果 → 标准化地理事件 → 同证据支持的业务流 → 统一地图查询 → USGS 外部事件 → 保守地区规则 → 待复核影响候选 → 人工复核 → 可审计回放。

内置浏览器自动控制组件验收时出现本机运行组件路径错误，未能建立自动化连接。这是 Codex 浏览器控制环境的问题，不是 TenderTrace 服务拒绝连接。报告因此没有伪造截图结论；页面仍可通过上方演示地址直接人工查看。

## 十、对既有功能的影响复核

### 10.1 无破坏性变更

- 未删除或改名任何原有 API；
- 未改变公告采集、机会评分、数字孪生、能力护照、变更引擎、关系图、飞书战情室和合作方尽调的数据语义；
- 五张新表使用独立名称，通过增量建表升级；
- 业务事件由已有公告派生，不回写公告原文；
- 影响候选不会改写机会、尽调或投标结论；
- 全量回归覆盖所有既有模块并全部通过。

### 10.2 修复的兼容问题

方向十六有一个数据库测试把版本号固定为 56。方向十七合法升级到 57 后，该旧断言失败，但 11 张方向十六数据表均完整存在。现已将测试改为验证“当前版本至少包含 56 且当前版本已登记”，继续严格检查所有尽调对象，避免后续正常增量迁移再次被旧版本号误判为回归。

### 10.3 性能和运行风险

当前构建会读取本地公告与最近外部事件，在 86 个当前主题事件下约 596 毫秒。外部同步只在明确操作时发生，不会阻塞普通页面进入。SSE 连接按 60 秒重连，不持有无限期连接。

## 十一、目前真实边界和风险

以下能力尚未被描述成“已完成”：

1. 外部事件目前只接入 USGS 地震，尚未正式接入台风、洪水、冲突、制裁、港口限制和关税变化；
2. 同国或半径规则只生成候选，尚未自动掌握每个项目的实际交付地址、供应链和运输路径；
3. 国际业务位置有 2 条仅到国家级，地图显示采用国家级定位，不代表精确项目地址；
4. 中国和全球底图使用本地示意边界，适合比赛态势展示，不用于测绘或导航；
5. “实时”是按来源分级的分钟级或显式同步，不承诺所有公开网站毫秒更新；
6. ReliefWeb 需要预先批准的应用名，当前未接入；
7. 自动浏览器截图验收受 Codex 本地浏览器控制组件路径错误阻塞，HTTP、API、JS 和布局契约已通过；
8. 当前影响确认是单人复核，生产环境可再增加双人审批和复核到期提醒。

这些边界不阻塞核心演示。它们通过页面标签、精度、时间、规则类型和人工状态显式展示，避免评委把候选关联误解为确定事实。

## 十二、后续提升建议

### 12.1 比赛前优先级 P0

1. 固定服务器主题的 90 秒演示路径和两个回放 ID；
2. 每次演示前运行 12 项自动验收及全量回归；
3. 为外部同步增加“最近成功时间”和网络失败演示预案；
4. 修复 Codex 内置浏览器控制组件后补录 1440×900 和 1920×1080 两档截图；
5. 在主讲稿中固定使用“影响候选”，避免口头说成“项目已受影响”。

### 12.2 产品深化 P1

1. 在完成许可验证后接入国内地震、台风和应急官方来源；
2. 为项目增加实际交付地、供应商工厂、仓库和运输节点；
3. 建立品类到 HS 编码、关税、贸易伙伴和生效时间的可解释映射；
4. 将人工确认的影响候选转成方向三的变更任务和方向八的飞书战情室任务；
5. 增加按事件前后比较机会数量、成交金额和地区异常的分析面板；
6. 为回放增加数字签名或发布清单，便于比赛设备间验证一致性。

### 12.3 长期方向 P2

1. 在数据量达到需要时引入空间数据库和事件分区；
2. 接入授权的港口、物流、关税和制裁数据；
3. 建立可复算的路线风险模型，但仍保留人工确认；
4. 将复核结果用于优化候选排序，不自动覆盖人工结论；
5. 扩展到供应链多跳关系和跨项目地区暴露分析。

## 十四、最终验收结论

方向十七已经达到“能跑、能展示、能核查、能回放、能解释边界”的比赛版本标准。真实机会、成交和供应流可以进入同一张地图；外部权威事件和项目影响候选严格分离；地图和列表口径一致；国内主案例省级定位率达到 100%；每个点、连线和影响关系均可进入证据；关闭动效后业务能力完整；离线回放有数据时间、核验状态和哈希；全量回归证明没有造成原有功能损失。

建议把方向十七作为全国总决赛的主视觉入口：先用地图建立“全国与全球态势”的第一印象，再点击真实成交流和外部事件候选证明系统不是视觉背景，而是一条能够回到公告、规则、证据、人工复核和执行动作的可信业务链。
