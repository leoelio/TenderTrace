## 二、原问题与本次解决目标

此前系统可以判断项目当前状态，但负责人难以安全回答以下问题：

1. 如果投标截止时间提前三天，团队是否还来得及？
2. 如果补齐伙伴授权，企业匹配和投标准备会改善多少？
3. 自主投标与联合伙伴投标之间，条件、风险和新增行动有什么差异？
4. 模拟结果是否会误写正式项目，导致已有任务、要求和人工裁决被污染？
5. 当历史样本不足时，系统会不会给出看似精确、实际不可验证的中标概率？

本次优化将上述问题转化为一个可复算、可解释、可审计、有人负责最终确认的决策沙盘。

## 三、设计方案与完整操作流程

### 3.1 双舱视觉结构

页面采用“正式基准 → 模拟方案”的双舱结构。左侧固定展示当前正式项目及状态指纹，右侧展示被选中的临时方案。中间箭头明确表达条件推演，而不是正式数据修改。

三项核心评分同时显示推演前、推演后和变化值：

- 机会价值
- 企业匹配
- 投标准备

分数下方提供“输入 → 影响 → 规则”的逐项解释。例如“投标截止提前3天 → 投标准备下降12分 → 每提前1天准备度下降4分”。评委不需要理解系统内部实现，也能说明每一个变化为何发生。

### 3.2 从第一步到最后一步的业务流程

1. **设置推演条件：** 输入方案名称和推演人，调整六类临时变量。
2. **运行并保存：** 系统读取正式基准快照，在隔离空间内计算结果并保存参数、基准哈希、规则版本、输出和创建人。
3. **查看变化：** 同屏展示评分变化、受影响要求、资源与任务负荷、风险方向和建议行动。
4. **复算历史方案：** 按保存时的基准和参数重新计算，并比较输出哈希。
5. **比较两个方案：** 生成三项评分差异、风险数量差异和条件解释，不显示中标概率。
6. **转为待确认建议：** 所选方案只进入待确认区，不创建正式任务。
7. **负责人裁决：** 负责人填写姓名与依据，可确认纳入或拒绝。
8. **进入正式计划：** 仅在确认纳入后，根据建议行动生成正式投标任务并写入审计事件。

### 3.3 页面易用性与展示效果

本次页面新增了以下视觉和交互设计：

- “沙盘隔离·正式数据只读”安全状态标识。
- 基准舱与模拟舱并列展示，并保留正式状态指纹。
- 三项评分的前后数字和升降颜色提示。
- 受影响要求、资源负荷、风险方向、建议行动四宫格。
- “不输出中标概率”边界声明。
- 历史方案卡片、选中态、复算按钮和转建议按钮。
- 双方案选择器和自动生成的比较结论。
- 待负责人确认、已纳入、已拒绝三种明确状态。
- 深色主题样式和窄屏响应式布局。

产品界面中没有出现“方向七”等内部研发编号，评委看到的是完整产品功能“投标决策沙盘”。

## 四、已完成的技术措施

### 4.1 数据模型

数据库模式升级到44，新增三类独立数据：

- `decision_scenarios`：保存方案名称、模式、参数、正式基准哈希、基准快照、规则版本、输出和创建人。
- `decision_scenario_suggestions`：保存待确认建议及负责人裁决结果。
- `decision_sandbox_events`：保存方案保存、复算、转建议和裁决事件。

沙盘数据没有复用正式要求、能力匹配或任务字段，因此不会因临时推演覆盖正式业务事实。

### 4.2 正式数据隔离

正式状态哈希覆盖以下核心对象：

- 公告主记录
- 投标要求
- 要求与企业能力匹配
- 会审案例
- 正式投标任务
- 项目结果复盘

自动化测试和演示样本均验证：运行方案与生成待确认建议前后，正式状态哈希完全一致。负责人确认后哈希发生变化，变化来源是有审计记录的正式任务创建，符合预期。

### 4.3 可解释规则

当前规则版本为 `decision_sandbox_v1`。每次评分变化均保存：

- 输入条件
- 变化前分值
- 变化后分值
- 分值变化
- 业务原因
- 适用规则

同时记录受影响的具体要求及影响原因，避免只给总分、不能说明依据。

### 4.4 不确定性控制

系统读取当前结果复盘与履约样本数量，但无论样本数量多少，本版本均不输出中标概率。页面只表达：

- 哪些条件改善或恶化
- 哪些风险仍然存在
- 需要新增哪些行动
- 哪个方案相对更有利

这避免了用不足样本制造虚假精确结论。

### 4.5 API与数字档案联动

已增加完整接口：读取沙盘、保存方案、复算、比较、转为建议和负责人裁决。数字项目档案同步显示已保存方案数量和待确认建议数量，并将人工裁决纳入项目时间线。

## 九、比赛演示建议

建议采用以下3分钟演示顺序：

1. 打开“政务云投标决策沙盘”，先指出绿色安全标识和正式状态指纹。
2. 选择“截止提前三天”，展示投标准备下降、受影响要求和新增风险。
3. 点击“复算”，展示相同参数得到相同结果。
4. 切换“联合伙伴补齐材料”，展示企业匹配和投标准备改善。
5. 点击两个历史方案的“生成对比结论”，说明系统比较条件而不预测中标概率。
6. 将方案转为待确认建议，说明此时正式状态不变。
7. 由投标总监填写依据并确认，展示行动进入正式计划。

评委追问“为什么可信”时，可直接回答：输入、规则版本、基准哈希、输出变化、创建人和人工裁决均被保存；同一方案可以复算；沙盘不会绕过负责人直接修改正式项目。
