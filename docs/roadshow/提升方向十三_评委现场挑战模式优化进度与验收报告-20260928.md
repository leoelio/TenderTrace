## 一、执行摘要

方向十三已经从方案条目落成可直接运行的“评委现场挑战”页面。评委不需要编写复杂自然语言，也不需要了解后台数据源，只需填写采购品类、地区、时间范围和可选关键词四个字段，即可现场发起检索。

本方向重点解决比赛现场最容易被质疑的四个问题：

1. **是否是预先写好的演示？** 每次查询生成独立会话编号，实时读取当前本地索引，结果协议明确标记 `replay_mode = false`。
2. **断网或外部网站失败怎么办？** 系统先返回本地已验证结果，联网补充由评委主动决定；外部来源失败不会清空本地结果。
3. **结果是否可以追溯？** 每条结果展示来源、发布时间、索引时间和原文入口，并可继续打开项目数字档案。
4. **现场输入会不会破坏系统？** 输入长度、控制字符、URL、提示词注入、路径穿越和SQL控制词均在后端拦截。

该能力与现有工作台共用数据库、检索引擎和机会数字档案，没有复制一套演示数据，也没有改变原有查询、机会研判、飞书协作或评测页面的行为。

## 三、评委操作流程

### 3.1 进入方式

- 在主导航点击“评委挑战”。
- 或直接打开 `http://127.0.0.1:8000/?view=challengeView`。

页面默认提供“服务器 / 全球 / 最近12个月”，该组合可以直接读取当前全国与全球机会索引。评委也可以改为任意指定品类、地区和时间窗口。

### 3.2 本地现场挑战

点击“开始现场挑战”后，系统立即执行以下动作：

1. 校验四个受控字段。
2. 将品类、地区和关键词分别写入检索意图，避免地区被误当成主题词。
3. 读取当前本地全文索引。
4. 记录实际响应毫秒数。
5. 保存查询会话与结果快照。
6. 在页面展示结果、来源状态和追溯入口。

### 3.3 联网补充

本地结果显示后，评委可以点击“联网补充”。系统以后台线程访问现有多来源适配器，页面轮询最新状态。

- 成功来源显示“可用”和新增数量。
- 访问受限或超时显示“暂不可访问”和原因。
- 与本次查询无关的来源显示“本次不适用”。
- 即使部分来源失败，本地结果仍保持可用。
- 点击“停止联网”后，系统立即标记取消，后续返回的联网结果不再写入该次挑战。

## 四、页面与交互验收

页面采用独立的比赛展示层，但保持TenderTrace现有视觉语言。页面从上到下包含：

1. 挑战标题与浏览器在线状态。
2. 四条可信规则：本地索引优先、原文可查、状态透明、自动留痕。
3. 四字段挑战表单。
4. 本地结果数、本地响应时间、联网新增数和数据时间。
5. 结果卡片、原文入口和数字档案入口。
6. 来源状态列表。
7. 历史挑战记录。

桌面端使用四列信息布局；在980像素以下切换为两列，在640像素以下切换为单列，结果操作区也转为横向按钮，避免小屏横向溢出。深色主题已有专门的指标色和提示色。

页面自动检查覆盖以下静态合约：

- 导航和 `challengeView` 存在。
- 四个受控字段存在。
- 本地优先、来源透明和自动留痕文案存在。
- 创建、联网补充和停止联网接口已绑定。
- 直达地址复制逻辑存在。
- 来源状态、结果卡片和移动端规则存在。

本机Codex内置浏览器自动控制组件本次出现环境级连接故障，因此没有生成自动化页面截图。真实HTTP页面返回200，HTML、CSS、JavaScript、API和交互合约均已验证；这项限制只影响自动截图取证，不影响项目页面运行。

## 六、数据与接口实现

### 6.1 数据库

数据库模式从49升级到50，新增两张表：

- `live_challenge_sessions`：保存四个输入字段、标准查询、检索意图、状态、耗时、结果数、来源摘要、取消状态、操作者和时间。
- `live_challenge_results`：保存会话结果、公告编号、结果来源、本地/联网标记、核验状态、原文、索引时间和展示顺序。

两张表使用独立前缀，不修改现有公告、机会、飞书、评测或业务价值表结构。联网补充遇到与本地相同的公告时不会覆盖本地已验证结果。

### 6.2 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/live-challenges` | 读取挑战历史 |
| POST | `/api/live-challenges` | 创建现场挑战并完成本地检索 |
| GET | `/api/live-challenges/{id}` | 读取完整会话与结果 |
| POST | `/api/live-challenges/{id}/supplement` | 启动联网补充 |
| POST | `/api/live-challenges/{id}/cancel` | 停止联网补充 |

联网补充在后台执行，前端可以继续展示本地结果并读取状态。API对不存在的会话返回404，对重复启动返回409，对非法输入返回400。

## 七、安全、真实性与失败隔离

### 7.1 受控输入

- 品类和地区最长30个字符。
- 关键词最长40个字符。
- 时间范围只能选择7天、30天、90天或365天。
- 拒绝控制字符、URL、系统提示词、提示词注入、密钥词、路径穿越和SQL控制词。
- 后端重新校验，不能通过修改前端绕过。

### 7.2 真实性边界

- 本地结果来自当前 `notices` 与全文索引。
- 联网结果来自本次现有适配器采集。
- 页面明确区分“本地已验证”和“联网新增·待核验”。
- 页面显示数据时间，不将历史索引伪装成刚刚发布。
- `generalization_allowed = false`，单次演示结果不用于推断全部业务效果。

### 7.3 失败隔离

自动化测试构造一个成功来源、一个超时来源和一个不适用来源，验证结果如下：

- 成功来源的公告正常落库。
- 超时来源显示“暂不可访问”和错误摘要。
- 不适用来源单独显示。
- 会话状态为 `completed_with_errors`，没有伪装成全部成功。
- 本地结果保留，联网失败不会造成空屏。

## 十、剩余边界与现场使用建议

1. 外部网站的可访问性会随网络、反爬策略和登录状态变化，因此联网状态必须以现场显示为准。
2. 比赛演示先执行本地挑战，确认结果出现后再由评委决定是否联网补充。
3. 本地索引的“数据时间”代表收录时间，不等同于外部网站此刻仍可访问。
4. 自动页面截图工具本次不可用；正式比赛前应在展示电脑上人工检查一次缩放比例、投影分辨率和字体显示。
5. 当前默认组合已经用真实索引验证有结果；比赛前仍建议运行一次验收脚本，确认本地数据库和服务状态。
