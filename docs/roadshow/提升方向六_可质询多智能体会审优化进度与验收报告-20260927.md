## 二、目标与验收口径

这项功能不是让多个 Agent 轮流输出一段文字，而是让五个专业角色在同一输入版本上互相形成“对手盘”：

1. **合规审查：** 资格条件、废标条款和合规风险；
2. **技术评审：** 技术参数、型号、接口和方案可实施性；
3. **商务评审：** 评分、预算、报价和商务条件；
4. **风险审查：** 截止窗口、资源依赖、证书有效期和执行门禁；
5. **证据审计：** 结论是否被可定位、当前有效的证据支持。

系统不得通过多数票制造“真相”。只有角色结论一致且引用有效证据时，汇总区才显示一致事实；结论冲突、证据冲突和低置信度必须显式保留并交给人员裁决。

## 三、完整操作流程

### 3.1 选择要求并锁定输入

用户从要求账本中选择已确认或待复核要求启动会审。系统保存：

- 会审案例 ID；
- 要求 ID；
- 公告修订 ID；
- 企业证据授权范围；
- 证据范围哈希；
- 提示版本；
- 请求的角色列表；
- 完整输入快照；
- 创建人和启动时间。

因此五个角色读取的是同一版公告、同一条要求和同一批企业证据，不会出现角色之间输入版本不同的问题。

### 3.2 五个角色独立审查

每个角色使用固定输出结构：

| 字段 | 作用 |
|---|---|
| 结论 | 同意有效、建议退回、建议升级 |
| 证据编号 | 只能引用输入中提供的要求证据或企业能力证据 ID |
| 判断理由 | 说明专业判断逻辑 |
| 风险 | 明确本角色发现的风险 |
| 待确认项 | 列出仍需人员或其他专业确认的问题 |
| 建议动作 | 把问题转换为下一步行动 |
| 置信度 | 表示该角色对自身判断的把握，不作为自动裁决依据 |

公告和企业材料按不可信引用数据处理。若检测到提示注入式文本，系统停止模型判断并转人工核验。

### 3.3 汇总一致事实与识别分歧

汇总器执行三条硬规则：

1. 不按票数选胜者；
2. 只有全部相关角色结论一致时才生成一致事实；
3. 分别标记 `conclusion_conflict`、`evidence_conflict` 和 `low_confidence`。

分歧卡并排展示角色、结论、证据编号、理由、风险、待确认项和建议动作。用户可以点击“打开双方证据”直接进入证据显微镜。

### 3.4 人工裁决

分歧进入人工裁决队列。裁决记录保存：

- 裁决结果；
- 裁决人；
- 裁决理由；
- 裁决时间；
- 对应要求和会审案例；
- 审计事件。

人工裁决后，会审案例变为已解决。再次运行同一案例时，系统扫描数量为零，原裁决和角色意见不会被覆盖。

### 3.5 角色失败与单独恢复

每次会审都有独立运行记录和恢复点。单个角色超时或失败时：

- 其他已完成角色意见立即保存；
- 整个案例不会回滚为零；
- 运行状态标记为 `completed_with_errors`；
- 页面显示失败角色和错误信息；
- 用户可以只重试失败角色；
- 恢复后历史失败记录仍保留，但“待恢复角色”归零。

### 3.6 公告变化增量复核

公告修订产生新的变更会审案例。系统根据要求类型只选择对应专业角色，并附加证据审计角色。例如技术要求变化时，仅运行技术评审和证据审计，不重复运行合规、商务和风险角色。

### 3.7 进入飞书与数字孪生

飞书会审卡片展示待裁决数量、分歧摘要和正式产品名称。数字孪生新增：

- 会审运行次数；
- 专业分歧数量；
- 当前未恢复角色数量；
- 人工裁决优先规则；
- “仅合并一致且有证据的事实”聚合规则。

## 六、验收标准逐项结论

| 验收标准 | 验收证据 | 结果 |
|---|---|---|
| 至少一个真实分歧案例 | 技术 accept、证据 reject、风险 escalate；汇总结果为结论冲突 | 通过 |
| 至少一个角色失败恢复案例 | 商务角色模拟超时，四条意见保留；只重试商务角色后恢复 | 通过 |
| 所有角色意见关联证据编号和公告版本 | 5 条主案例意见均有 requirement/capability 证据 ID 和 `review-opponent-rev-1` | 通过 |
| 人工裁决后重跑不能覆盖 | 裁决后重跑 `scanned_case_count = 0`，原意见更新时间不变 | 通过 |
| 任一角色失败不丢其他意见 | 首次运行完成 4 条、失败 1 条；失败运行有恢复点 | 通过 |
| 分歧到双方证据打开时间不超过五秒 | 本地真实 HTTP：会审面板 829 ms，证据显微镜 324 ms | 通过 |
| 公告变化只复核受影响部分 | 技术变化只请求 `technical + evidence_audit` | 通过 |

## 九、已知边界与后续建议

1. 演示中的模型输出由确定性演示网关生成，目的是稳定证明分歧、失败恢复和人工裁决流程；正式运行时使用当前配置的模型服务。
2. 角色置信度只表示角色自身把握，系统不会把它转换为自动决策或中标概率。
3. 公告变化增量复核依据要求类型选择专业角色；涉及跨专业合同条款时，负责人仍可手动选择更多角色运行。
4. 飞书真实发送依赖当前应用权限和接收群配置；代码路径和卡片生成已通过回归，比赛前应向演示群发送一次最终会审摘要。
5. 当前 Codex 内置浏览器控制组件路径缺失，无法生成自动页面截图。页面已通过 JavaScript、CSS、静态入口、真实 HTTP/API 和运行服务验证。

## 十、总结

“可质询多角色会审”已经从基础的多角色意见列表升级为真正可追问、可反驳、可恢复、可人工裁决的专业对手盘。每条意见都绑定公告版本和证据编号；系统不以投票代替事实；一个角色失败不会使流程归零；人工裁决不会被后续运行覆盖；公告变化只触发受影响角色。该功能与企业能力护照、证据显微镜、飞书会审和数字孪生使用同一要求与证据链，能够作为全国总决赛现场的一项独立核心展示。
