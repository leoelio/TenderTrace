# TenderTrace 可复算业务价值实验室优化进度与验收报告

**报告日期：** 2026年9月28日  
**独立验收对象：** 提升方向十二——可复算的业务价值实验室  
**产品落位：** 主导航“评测与价值” > 业务价值实验室  
**实现验收结论：** 通过；实验协议、数据采集、人工金标门禁、复算公式、失败/异常展示、十八方向映射、审计历史和低样本保护均已实现并验证  
**真实业务收益结论：** 尚未形成；正式库当前为0个真实人员配对样本，系统明确显示“暂无完整配对实验，不能估算业务收益”

## 一、执行摘要

本方向没有再创建一个与现有功能割裂的独立工具，而是将原有“Agent评测”升级为“评测与价值”。同一个页面分成两个相互关联但口径严格分开的区域：

1. **业务价值实验室：** 回答系统是否减少人工时间、遗漏、错误满足判断和返工。
2. **工程稳定性证据：** 回答自动化测试、RAG、Harness、召回和Agent链路是否稳定。

系统不会用自动化测试数量、页面点击量或模型自评分代替业务收益。业务价值百分比只从同一任务、同一文件的人工基线和TenderTrace辅助配对记录中计算；质量结果必须经过人员金标复核。

已经完成的核心结果：

- 将总耗时、人工有效时间和机器等待时间分开记录。
- 记录关键要求遗漏、错误满足判断和返工次数。
- 记录实验编号、版本、参与人、文件类型、文件数、交叉顺序和实验条件。
- 每个质量通过样本必须保留原始计时记录入口和人工金标入口。
- 页面显示中位数、范围、合计复算和每一个单独样本。
- 失败样本、负向样本和异常值不会被隐藏。
- 六类指标均公开公式、分子、分母、单位和样本量。
- 十八个已规划提升方向统一映射到业务任务类型，分别显示“已实测”或“待实测”。
- 每次样本更新保留不可变快照，便于复核历史版本。
- 样本少于5个时只展示当前样本，不做总体外推；达到5个也仍不承诺未来收益。
- 全项目回归518项测试、582项子测试全部通过，0项失败。

## 二、原功能差距与本次目标

项目原先已经有一个“业务价值实测”表单，但只能填写任务类型、样本编号、人工分钟、辅助分钟和质量结果。它具备“不用点击量估算节省”的正确方向，但还不能支持严谨实验。

原功能存在以下缺口：

| 原功能 | 风险 | 本次处理 |
|---|---|---|
| 只记录两段总时间 | 无法区分机器等待和人员真正投入 | 分开记录机器等待、人工有效时间和总耗时 |
| 没有实验编号和版本 | 新旧实验条件容易混在一起 | 新增实验编号、版本与历史快照 |
| 没有参与人与文件类型 | 无法解释样本构成 | 明确参与人、文件类型、文件数量和实验条件 |
| 没有交叉顺序 | 熟练度偏差无法观察 | 记录先人工、先辅助或随机交叉 |
| 没有质量错误字段 | 只能证明快，不能证明是否漏项 | 增加遗漏、错误满足判断和返工次数 |
| 质量复核没有金标入口 | 模型可能间接给自己打分 | 已复核记录必须绑定人工金标入口 |
| 只展示合计值 | 容易只挑最好结果 | 展示中位数、范围和全部单样本 |
| 负结果被截断为0 | 会隐藏系统表现较差的样本 | 保留负向差值，异常值仍计入并展示 |
| 与其他提升方向没有关系 | 无法解释“十几个方向带来什么价值” | 建立十八方向到十六类业务任务的价值链映射 |

## 三、产品融合与用户体验

### 3.1 为什么放在“评测与价值”

业务价值与Agent评测有关，但二者证明的事实不同。把它们放在同一页面，用户可以连续回答两个问题：

- 产品是否稳定、可追踪、可复现？看工程稳定性证据。
- 产品是否真的让业务人员更快、更少漏项？看业务价值实验室。

页面使用明确分隔标题“工程稳定性证据”，避免把自动测试数量误当成业务节省。

### 3.2 页面阅读顺序

业务价值区域位于页面上方，按照普通用户最容易理解的顺序排列：

1. 当前实验状态：可计算、样本不足或尚未实测。
2. 六个概览指标：有效样本、参与人、文件、时间中位数、样本内降低率、失败/异常数。
3. 实验协议：同一文件、交叉顺序、计时口径和金标要求。
4. 十八方向价值链：每个提升方向对应什么任务、是否已有有效样本。
5. 六类配对结果：人工中位数、辅助中位数、变化范围。
6. 实验批次和复算公式。
7. 全部原始样本，包括失败样本和异常值。
8. 默认折叠的录入表单，需要时再展开。

### 3.3 录入表单

录入表单分成四组：

- 样本与实验条件。
- 配对时间记录。
- 人工金标质量对照。
- 复算与审计证据。

复杂字段被分组并默认折叠，不会占满主页面。保存后页面立即重新复算，不需要人工维护宣传数字。

## 四、业务价值实验协议

### 4.1 推荐实验规模

- 使用5至10份公开招标文件。
- 每份文件使用固定任务清单。
- 同一份文件分别执行人工基线和TenderTrace辅助处理。
- 参与人至少2名，人工优先和辅助优先交叉分配。
- 使用相同的计时起点、终点和允许工具。

### 4.2 时间指标

每一侧分别记录：

1. **机器等待时间：** 下载、解析、模型运行或页面等待时间。
2. **人工有效时间：** 人员实际阅读、判断、录入和复核时间。
3. **总耗时：** 从任务开始到提交完成的完整时间。

人工有效时间不得大于该侧总耗时。机器等待时间单独展示，避免把“人没有操作”误写成“系统没有耗时”。

### 4.3 质量指标

使用人工金标对照：

- 关键要求遗漏数。
- 错误满足判断数。
- 返工次数。
- 质量复核通过或未通过。

质量通过样本必须填写参与人、文件类型、实验条件、原始计时记录、人工金标和复核人。缺少任一项时，样本可以保存和展示，但不会进入价值百分比。

### 4.4 交叉顺序

系统支持：

- 先人工后辅助。
- 先辅助后人工。
- 随机交叉顺序。

页面按实验批次展示使用过的顺序，便于检查是否所有样本都以同一种顺序完成。

## 五、可复算指标和公式

六类指标使用同一对照公式：

> 降低率 =（人工基线合计 - 系统辅助合计）÷ 人工基线合计

页面同时显示：

- 当前样本的基线合计。
- 辅助合计。
- 差值合计。
- 降低率。
- 人工与辅助中位数。
- 单样本差值范围。
- 每个样本的原始配对值。

指标包括：

| 指标 | 单位 | 业务解释 |
|---|---|---|
| 总耗时降低率 | 分钟 | 一项任务从开始到完成的整体变化 |
| 人工有效时间降低率 | 分钟 | 真正减少了多少人员投入 |
| 机器等待时间变化 | 秒 | 自动处理带来的等待成本 |
| 关键要求遗漏降低率 | 项 | 是否更少漏掉强制要求 |
| 错误满足判断降低率 | 项 | 是否减少把缺口误判成满足 |
| 返工次数降低率 | 次 | 是否减少交付后的重复修改 |

如果人工基线合计为0，系统不会进行除零或生成伪百分比，而是保留绝对值并显示无法计算比例。

## 七、数据与审计实现

### 7.1 数据库升级

数据库模式从48升级到49。原 `business_measurements` 表保留并扩展，不破坏已有接口和旧记录。

新增字段包括：

- 实验编号与版本。
- 参与人、文件类型、文件数量。
- 交叉顺序与实验条件。
- 公开文件、原始记录、人工金标入口。
- 两侧人工有效时间和机器等待时间。
- 两侧遗漏、错误满足和返工次数。
- 异常值标识和异常原因。

新增 `business_measurement_events`，每次保存或更新样本时写入完整快照、操作者和时间。主记录可以更新，历史证据不会被覆盖。

### 7.2 接口

- `GET /api/evaluations/business-measurements`：读取实验总览、指标、公式、批次、方向覆盖和全部样本。
- `POST /api/evaluations/business-measurements`：保存一组配对实验并返回重新计算后的结果。
- 原 `GET /api/evaluations/agent` 继续返回业务价值摘要，保持评测页面兼容。

### 7.3 数据保护

- 不允许负数计时或错误数量。
- 人工有效时间不得大于总耗时。
- 已复核样本必须填写复核人与人工金标入口。
- 质量通过样本必须具备完整证据。
- 标记异常值时必须填写异常原因。
- 证据入口只接受HTTP(S)或应用绝对路径，防止危险协议被前端打开。

## 十三、实际操作指南

### 13.1 准备实验

1. 从真实公开来源选择5至10份招标文件。
2. 为每份文件确定固定任务，例如拆出全部强制条款和评分项。
3. 先制作人工金标，金标人员不要查看系统答案。
4. 安排至少2名参与人，并交叉安排人工优先与系统优先顺序。
5. 统一说明允许使用的工具和计时起止点。

### 13.2 记录一个样本

1. 打开“评测与价值”。
2. 展开“录入一组配对实验”。
3. 填写实验编号、版本、任务类型、样本编号和参与人。
4. 填写文件类型、交叉顺序、实验条件和公开文件入口。
5. 分别填写人工和辅助的总耗时、有效时间和等待时间。
6. 对照金标填写双方遗漏、错误满足和返工次数。
7. 填写原始计时记录、人工金标、复核人和说明。
8. 保存后检查样本是否显示“证据完整”。

### 13.3 检查结论

1. 先看有效样本数和参与人数。
2. 确认实验条件和交叉顺序没有混用。
3. 查看中位数，不只看合计百分比。
4. 查看差值范围，确认是否包含负向样本。
5. 展开异常值原因，并打开原始记录和金标。
6. 现场用页面分子和分母复算一个指标。

## 十四、比赛展示脚本

建议用60至90秒展示：

1. 打开“评测与价值”，先说明工程稳定性和业务价值是两套证据。
2. 指出实验只接受同一文件的人工与辅助配对记录。
3. 展示十八方向价值链，说明每个能力最终要落到具体业务任务。
4. 打开总耗时或遗漏指标，展示中位数、范围和样本量。
5. 打开一个失败样本或负向异常值，说明系统没有只挑最好结果。
6. 展开复算公式，现场演示分子除以分母。
7. 展示原始记录和人工金标入口。
8. 如果真实实验尚未完成，直接说明当前为0个正式样本，系统不生成宣传百分比。

推荐讲解句：

> 自动化测试证明系统稳定，配对实验才证明业务价值。每个百分比都能回到参与人、文件、原始计时和人工金标；系统表现不好的样本也保留。

## 十五、风险边界与下一步

1. 受控验收夹具不能代替真实人员实验，也不能出现在商业宣传数字中。
2. 当前正式库没有真实样本，因此不能回答“实际节省了多少”。
3. 5个样本只达到小样本展示门槛，不代表所有行业、人员和项目。
4. 不同任务类型不能混在一起计算总降低率，应优先查看各任务类型结果。
5. 参与人熟练度、文件复杂度和网络环境会影响结果，必须保留实验条件。
6. 后续可以增加盲法金标和样本随机分配，但当前无需引入复杂统计平台。

下一步执行顺序：

1. 由项目组确定2名实际参与人。
2. 选择5至10份真实公开招标文件。
3. 先完成一个任务类型，例如“招标要求拆解”，避免混合口径。
4. 完成人工金标、配对计时和复核。
5. 数据进入实验室后再更新路演中的业务百分比。
6. 逐步覆盖机会发现、能力匹配、变更复核、会审、协作和材料复用。

## 十六、最终结论

可复算业务价值实验室已经达到“实验条件清楚、指标可以复算、质量由人工金标、失败和异常不隐藏、十八方向统一追踪、样本不足不夸大”的产品实现目标。

系统实现、数据库、接口、页面、受控验收、专项测试和全量回归均已通过。正式业务收益仍是待完成事项，因为项目没有真实参与人的配对实验记录。当前系统选择显示“不能估算”，而不是填入虚构数字；这正是本方向可信性的核心。
