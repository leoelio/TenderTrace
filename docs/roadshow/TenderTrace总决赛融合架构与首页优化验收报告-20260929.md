# TenderTrace 总决赛融合架构与首页优化验收报告

**验收日期：** 2026 年 9 月 29 日  
**本地地址：** <http://127.0.0.1:8000/>  
**验收对象：** 融合产品架构、总决赛首页、七分钟展示链路、新增数据源可行性、项目回归与运行环境  
**单项报告：** [提升方向一至十八独立验收报告索引](提升方向一至十八独立验收报告索引-20260929.md)

## 一、验收结论

本轮融合优化达到“可运行、可连续演示、数据口径诚实、原有功能可回到、失败边界可说明”的目标。

总决赛首页已经成为默认首页，用一条连续业务主线串联机会发现、项目判断、证据核验、风险处理、飞书执行和训练复盘。主导航收敛为“机会、项目、企业、战情图、训练、协作”六个业务入口，原检索工作台、评委挑战、演示控制台、历史运行、订阅、数据源、评测、用户记忆和设置全部保留在“更多工具”中，没有删除原功能。

本机服务和数据库正常，首页与核心接口 HTTP 200。全量回归为 565 项测试通过、628 个子测试通过；前端 8 项测试通过；JavaScript 语法和 Ruff 检查通过。没有发现本轮首页与架构融合造成既有功能损失。

当前不能说“所有外部数据源全部正常”：16 个已配置采购来源中 14 个健康、1 个降级、1 个异常。USGS 外部事件源已接入且本次探测 HTTP 200；国家企业信用信息公示入口只适合作为人工或授权核验；ReliefWeb 和 WTO 官方接口具备接入可行性，但项目尚未配置所需 appname、API key 和业务映射。

## 二、四层融合产品架构

### 2.1 数据与事件层

这一层负责回答“事实从哪里来”。现有数据包括采购公告、结果公告、附件、企业材料、合作方资料、飞书记录、组织记忆、外部地震事件和人工补充证据。每条可用于决策的内容应保留来源、采集时间、原文位置和状态。

对应产品入口：机会雷达、数据源、检索工作台、企业尽调、飞书协作。

### 2.2 可信情报层

这一层负责回答“这些事实是否足够可信”。系统使用投标数字孪生、证据显微镜、来源关系图、合作方尽调和外部事件影响候选，把来源冲突、证据缺口、变化和人工确认集中到同一条审计链。

对应提升方向：一、二、三、十、十一、十六、十七。

### 2.3 决策与执行层

这一层负责回答“现在应该做什么”。要求拆解、能力匹配、多角色会审、决策沙盘、战情室、任务、日历和公告变更响应使用同一项目与要求标识，避免在页面之间复制出互不一致的任务。

对应提升方向：四、五、六、七、八、十三、十四。

### 2.4 学习与复盘层

这一层负责回答“下次怎样做得更好”。企业投标记忆体、组织记忆、业务价值实验室和情景训练保留成功材料、失败教训、人工反馈、实验条件和训练回放。系统不把受控夹具或工程测试数量冒充业务收益。

对应提升方向：九、十二、十五、十八。

### 2.5 贯通标识

全链路围绕五类核心对象组织：

| 对象 | 作用 | 主要落点 |
|---|---|---|
| 项目 | 串联公告、评分、要求、任务和结果 | 数字孪生、项目驾驶舱 |
| 企业 | 串联我方能力与外部合作方 | 能力护照、企业尽调 |
| 证据 | 支撑或反驳业务判断 | 证据显微镜、来源关系图 |
| 事件 | 表达公告变化和外部变化 | 变更影响、战情图 |
| 任务 | 把判断转成负责人和截止时间 | 作战图、飞书任务、训练补强 |

## 三、总决赛首页优化

### 3.1 首页要解决的三个问题

1. 现在有哪些值得看的机会；
2. 主案例是否值得投、准备到什么程度；
3. 当前最紧急的风险和下一步行动是什么。

首页不堆放详细配置、完整评测表和历史运行日志。这些专业功能仍在“更多工具”中按需打开。

### 3.2 首页已实现内容

- 默认打开“总决赛”首页；
- 顶部展示一条业务主张：从公开机会到可执行投标决策；
- 提供主案例、评委挑战和刷新入口；
- 提供一句话业务入口，可识别机会、企业风险、区域态势和训练意图；
- 左侧显示全国机会雷达和来源覆盖；
- 中间显示主案例的机会价值、企业匹配度、投标准备度和证据；
- 右侧显示紧急风险、阻塞项和下一步动作；
- 展示四层产品架构和七分钟路演路线；
- 明确区分已接入来源、候选来源和需要人工或授权的来源；
- 底部显示数据时间、本地状态、飞书状态和回放状态。

### 3.3 导航调整

主导航为：总决赛、机会、项目、企业、战情图、训练、协作。

“更多工具”保留：检索工作台、评委挑战、演示控制台、历史运行、订阅管理、数据源、评测与价值、用户记忆、设置。

本轮只调整入口层级，没有删除页面、接口、数据库表或已有操作。

### 3.4 首页性能处理

首页调用 `/api/demo-reliability?compact=true` 获取精简的演示状态。实测精简响应 15,534 字节，完整响应 383,267 字节，首页首轮传输减少约 95.9%。默认完整接口保持原样，原演示控制台不受影响。

## 四、七分钟连续演示路线

现场只讲一个真实项目，不在十八个方向之间来回跳转。

| 时间 | 演示动作 | 页面 | 评委得到的结论 |
|---|---|---|---|
| 00:00-00:30 | 首页开场 | 总决赛首页 | 系统把公开信息转成可执行投标决策。 |
| 00:30-01:10 | 发现真实机会 | 机会雷达 | 机会有来源、有时间、有健康状态。 |
| 01:10-02:00 | 判断是否值得投 | 项目数字孪生 | 三项评分可解释，风险和下一步清楚。 |
| 02:00-03:10 | 放大证据与变化 | 证据显微镜、变更影响 | 结论能回到原文，变化能定位受影响对象。 |
| 03:10-04:10 | 核验企业与合作方 | 能力护照、企业尽调 | 我方能不能做与对方值不值得合作分开判断。 |
| 04:10-05:10 | 形成执行计划 | 拆标、会审、决策沙盘 | AI 输出进入人工裁决和任务，不直接替人决定。 |
| 05:10-06:20 | 进入飞书执行 | 协作空间、战情室 | 群、表格、任务、日历和回写组成闭环。 |
| 06:20-07:00 | 训练与收束 | 情景训练 | 团队用同一证据接受追问，结果可回放、可复算。 |

推荐主案例为“中国人民银行集中采购中心 ARM 服务器采购项目”，项目标识为 `pbc_procurement:04b40d52-b636-11f1-88d4-b4055dfb2cc6`。该案例已经进入演示可靠性控制台并保留真实来源。

## 五、新增数据源可行性

### 5.1 已配置采购来源

2026 年 9 月 29 日运行态实测：

| 状态 | 数量 | 说明 |
|---|---:|---|
| 健康 | 14 | 包括全国公共资源交易平台、人民银行集中采购、中直采购、TED、UNGM、World Bank、千里马等。 |
| 降级 | 1 | 中国政府采购网 `ccgp`，历史成功但当前页面访问超时，必须在页面显示降级。 |
| 异常 | 1 | 亚洲开发银行 `adb`，当前 HTTP 403，不用于现场实时采集承诺。 |

机器可读证据见 [新增数据源可行性审计 JSON](../demo/finals_source_feasibility_20260929.json)。

### 5.2 USGS

项目已经使用 USGS M4.5+ 月度 GeoJSON Feed。官方说明表明 GeoJSON Feed 面向程序化使用，近实时 Feed 会持续更新：[USGS GeoJSON Feed](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php)。本次本机探测 HTTP 200，返回 511 条事件。

保留规则：地震事实和投标影响分开保存。距离、国家或业务流规则只生成待人工复核的影响候选，不自动认定项目受影响。

### 5.3 国家企业信用信息公示系统

[国家企业信用信息公示系统](https://bt.gsxt.gov.cn/)适合使用企业名称、统一社会信用代码或注册号进行官方主体核验。本机直接访问返回 HTTP 412，项目也没有配置公开稳定的自动接口。

当前决策：比赛阶段作为“人工官方核验”入口或以后使用正式授权接口，不做自动绕过访问限制的抓取。

### 5.4 ReliefWeb

[ReliefWeb API 文档](https://apidoc.reliefweb.int/)可正常访问。官方接口适合获取灾害和人道事件，但从 2025 年 11 月 1 日起要求预先获批的 `appname`，并有调用配额和署名要求。

当前决策：技术可行，尚未接入。先申请 appname，再实现缓存、限流、来源署名、事件去重和影响候选规则。

### 5.5 WTO

[WTO Tariff & Trade Data](https://www.wto.org/english/tratop_e/tariffs_e/tariff_data_e.htm)覆盖 150 多个经济体；[WTO API Developer Portal](https://apiportal.wto.org/)提供需要 API key 的数据服务。

当前决策：技术可行，尚未接入。先取得 API key，并建立项目品类到 HS 编码、国家/地区和生效日期的映射，才能把关税变化转成可解释的项目影响。

### 5.6 现场表达边界

- “已接入”只用于代码和运行证据都存在的来源；
- “可行”表示官方接口、许可和技术路线成立，不表示已经开发完成；
- “实时”必须同时显示数据时间和刷新方式；
- 任何来源失败时保留最后成功时间和错误，不用缓存掩盖故障。

## 六、飞书融合状态

飞书总状态为 `ready`，消息发送、报告交付、周报、多维表格、任务同步、截止日历、卡片回调、机会卡片、组织协作和长连接命令均已具备运行条件。长连接监听器在本轮重启后为 `running`，已有成功发送回执。

独立飞书智能体应用属于可选扩展。未启用时接口返回 `agent_service.ready=true`、`optional=true`、`enabled=false`，并明确说明现有机器人、任务、表格、日历、组织协作和长连接继续使用消息应用，不再把未启用的可选扩展误报为故障。

## 八、当前限制和比赛前动作

1. `ccgp` 已在直连受限时自动切换本机浏览器抓取，比赛前仍需执行一次最新采集确认；
2. `adb` 直连仍受 Cloudflare 限制，现已通过公开网页阅读中继恢复，并在数据中保留 `retrieval_via`；比赛网络不可访问中继时使用本地最近成功数据；
3. 申请 ReliefWeb appname 和 WTO API key 后再进入适配器开发；
4. 企业工商数据保持人工核验，除非取得明确授权接口；
5. 完成方向十二的正式业务实验样本，才能声明具体提效比例；
6. 完成方向十八至少 5 名真实参与者前后测，才能声明团队能力提升；
7. 比赛前再次确认飞书群成员、任务接收人、日历权限和投屏网络；
8. 使用演示可靠性控制台完成三轮连续彩排，并保留离线回放。

## 十、最终判定

融合产品架构、总决赛首页和七分钟连续演示路线验收通过。项目可以继续进入用户手动体验和路演彩排。验收不掩盖外部来源、正式业务样本和真人训练样本的限制；这些项目按本报告列出的前置条件继续推进，不影响现有核心产品演示。
