# TenderTrace 路演事实与数据口径台账

核验日期：2026-09-04

用途：约束 PPT、GIF、逐字稿和答辩中的事实表述。所有数字先判断证据等级，再决定是否展示。

## 1. 证据等级

| 等级 | 定义 | 路演使用方式 |
|---|---|---|
| A | 本次在当前工作区重新运行并通过 | 可以陈述，必须保留命令输出或产物 |
| B | 代码和自动化测试证明能力存在，但未完成真实外部服务联通 | 可以说明“已实现”，不能声称现场联通或实际业务收益 |
| C | 历史运行或历史产物存在，本次未重新联网验证 | 只能说明历史样例和具体时间，不能写成当前实时状态 |
| D | 规划能力、推测收益或尚未完成的功能 | 不作为成果陈述；必要时明确标注“待完成”或“下一阶段” |

## 2. 当前可以使用的事实

### 2.1 自动化测试

- 结论：365 项 Python 测试、456 项子测试通过。
- 等级：A。
- 核验命令：`.venv\Scripts\python.exe -m pytest -q`
- 核验结果：`365 passed, 456 subtests passed in 28.06s`
- 可以说：当前代码库的 365 项自动化测试全部通过。
- 不能据此说：系统已在所有真实来源、飞书租户和现场网络中完整运行。

### 2.2 交付验收

- 结论：34 项验收检查通过，0 项警告，0 项失败。
- 等级：A。
- 核验命令：`.venv\Scripts\python.exe -m tendertrace acceptance-check --no-runtime`
- 核验范围：交付文档、安全扫描、数据库结构、模型配置、基础来源配置、历史 Word 产物、历史运行与模型审计记录。
- 可以说：当前提交工作区通过 34 项交付与配置验收检查。
- 必须说明：使用了 `--no-runtime`，不代表本次重新执行了外部采集、模型调用和飞书投递。

### 2.3 来源覆盖

- 结论：`source-status` 返回 16 个已配置来源。
- 等级：A（配置存在）；真实运行健康度分别按 B 或 C 处理。

- 可以说：系统配置了 16 个来源适配器，并按国内、国际和登录态范围路由。
- 不能说：16 个来源在本次核验中全部实时采集成功。

- 不能将某个来源的历史成功率写成全系统实时成功率。

## 3. 当前只能说明“代码已实现”的能力

### 3.1 飞书集成

- 代码基础：机器人消息、多维表格、Task v2、日历、项目群、交互卡片、回调、组织记忆和状态同步。
- 等级：B。
- 当前环境核验：`feishu-status` 返回 `enabled=false`、`configured=false`，App ID、App Secret 和默认接收目标均未配置。
- 可以说：仓库已经实现飞书相关接口和自动化测试。
- 当前不能说：本机已连通真实飞书租户，或现场可以直接完成真实消息、任务和日历同步。
- 升级为 A 级证据所需条件：配置比赛使用的飞书应用，在指定租户完成一次群、卡片、多维表格、Task v2、日历和回写的端到端录像及日志留存。

### 3.2 公告变更与决策失效

- 代码基础：`notice_revisions`、重大变化分级、复核时限、旧决策失效和审计事件。
- 等级：B。
- 可以说：系统实现了公告版本变化触发决策复核的状态逻辑。
- 升级为 A 级证据所需条件：准备一组真实公告与补充公告，运行前后版本导入并录制决策失效、复核和重新决策全过程。

### 3.3 组织记忆与投标复盘

- 代码基础：个人行为记忆、飞书项目群隔离记忆、事实/行动转换、中标与失标结果、败因和竞争样本。
- 等级：B。
- 可以说：系统实现了记忆与复盘数据结构和业务动作。
- 不能说：系统已经通过大量企业历史投标数据提升实际胜率。

## 4. 当前不得作为已完成功能陈述

### 4.1 智能拆标要求账本

- 等级：D。
- 当前状态：现有代码只对正文中的需求维度做关键词覆盖检查，没有逐条要求表、页码级证据、人工状态和要求级负责人。
- 完成标准：建立数据库模型、抽取流程、证据定位、人工编辑、API、界面和人工标注评测。

### 4.2 五个领域 Agent 会审

- 等级：D。
- 当前状态：TenderGraph 主流程为意图、采集、证据和报告四个节点，没有文书、合规、技术、商务和证据审计五类会审节点。
- 完成标准：节点输出进入同一要求账本，具备分歧识别、低置信度复核、人工确认优先和 checkpoint 恢复。

### 4.3 豆包工作伙伴参与

- 等级：D。
- 当前状态：仓库未发现豆包、火山引擎或工作伙伴的实现和配置。
- 培训口径：豆包工作伙伴是推荐项而非强制绑定项，但主持人口头说明本届至少要使用一个飞书 AI 工具。
- 证据边界：使用“效傲 X 分钟”Skill 打磨路演属于备赛过程，不能据此声称 TenderTrace 产品已经接入豆包工作伙伴或飞书 AI。
- 完成标准：先取得赛区群或 Coach 的书面认定口径；若要求产品接入，必须完成真实调用、权限边界、审计记录和现场证据。

### 4.4 企业能力库和知识图谱

- 等级：D。
- 当前状态：组织记忆、机会事实和结果复盘已经存在，但没有完整的企业资质、产品、案例、人员、伙伴和招标要求关系模型。
- 完成标准：建立实体模型、证据来源、人工维护入口和要求匹配逻辑。

## 5. 必须补做的量化证据

以下数字在完成测试前全部写为“待确认”，不得填入 PPT：

| 指标 | 建议口径 | 最低证据要求 |
|---|---|---|
| 招标检索耗时变化 | 人工完成同一任务的时间与系统流程时间 | 同一任务、同一网络和同一结果要求，多次计时 |
| 拆标耗时变化 | 人工阅读并形成要求表的时间与系统生成加人工复核时间 | 至少 3 套公开招标文件 |
| 强制条款召回率 | 人工金标中的强制条款被系统识别的比例 | 双人复核金标、保留原文位置 |
| 截止时间准确率 | 识别正确的日期、时间和时区占输出数量的比例 | 覆盖正文、附件和补充公告 |
| 评分项召回率 | 人工金标评分项被识别的比例 | 明示权重与无明示权重分开统计 |
| 飞书任务同步成功率 | 成功创建且状态可回写的任务数占尝试数 | 真实租户、保留任务 ID 的脱敏日志 |
| 端到端完成时间 | 从输入需求到形成可分工要求账本的总时间 | 明确是否包含网络采集和人工确认 |

## 6. PPT 数字使用规则

- 每个数字在备注中记录来源文件、命令、日期、样本数和统计方法。
- 页面先说变化，再说明口径，最后解释业务意义。
- 配置数量、代码测试、历史运行和真实业务效果必须分开表述。
- 代理指标不得改名为准确率、召回率或业务收益。
- 历史截图必须显示或注明采集日期。
- 尚未完成的功能使用“计划完成”或“开发中”，不能用完成态 GIF 或固定结果冒充真实运行。
