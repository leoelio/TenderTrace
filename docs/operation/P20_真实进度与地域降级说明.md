# P20 真实进度与地域降级说明

## 目标

本阶段修复两个体验和可信度问题：

1. Web UI 运行时不能一次性把所有步骤显示为“运行中”，必须展示真实阶段进度。
2. 当用户查询“杭州市”但城市级检索无结果时，系统不能直接把结果说成“浙江省”。如果发生地域降级，必须明确说明：杭州城市级检索未命中样本，已扩大到浙江省内检索，结果可能来自省内周边城市。

## 实现变更

### 后台运行接口

新增 `POST /api/runs/start`。

该接口立即返回 `run_id` 和 `queued` 状态，然后在后台线程执行 `run_once`。前端拿到 `run_id` 后轮询：

- `/api/runs/{run_id}`
- `/api/checkpoints/{run_id}`
- `/api/traces/{run_id}`

这样 UI 可以根据真实 checkpoint 推进，而不是用定时器模拟全流程。

涉及文件：

- `tendertrace/app/api.py`
- `tendertrace/runner.py`
- `web/dist/app.js`

### 地域降级结构化

`MultiSourceAdapter` 已经在来源统计中记录 `relaxed_city=true`。P20 将这个事实汇总为 `region_scope`：

```json
{
  "status": "relaxed_city",
  "requested_city": "杭州",
  "requested_province": "浙江",
  "fallback_region": "浙江",
  "message": "杭州城市级检索未命中样本，已扩大到浙江省内检索；结果可能包含省内周边城市，请以来源链接为准。"
}
```

该字段写入 run stats，并注入 BidQL `meta.region_scope`，因此 Web UI、事件追踪和 Word 报告都读取同一个事实来源。

涉及文件：

- `tendertrace/runner.py`
- `tendertrace/report/docx_writer.py`
- `web/dist/app.js`

### Web 进度卡

前端移除了多条模拟进度消息，改为单个进度卡：

- 阶段：意图解析、数据采集、内容质检、生成报告。
- 状态：等待、进行中、已完成。
- 明细：来源采集条数、地域降级说明、证据通过数、附件正文数、Word 写入状态。

运行过程中，只有当前阶段显示“进行中”，未到达阶段显示“等待”，已完成阶段显示“已完成”。

### Word 报告说明

当发生城市级降级时，报告头部会写入：

- `地区：杭州（城市级无结果，已扩大至浙江省内）`
- `地域范围说明：杭州城市级检索未命中样本，已扩大到浙江省内检索；结果可能包含省内周边城市，请以来源链接为准。`

## 验证

```text
最近36个月杭州市的空调或者服务器投标信息都有哪些
```

- 命中 3 条记录。
