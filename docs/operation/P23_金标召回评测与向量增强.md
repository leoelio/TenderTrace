# P23 金标召回评测与向量增强

本阶段解决“改进是否真的提升召回”的证明问题。系统不再只展示 `recall_proxy`，而是支持人工金标集驱动的真实 `Recall@K`。

## 1. 金标基准

金标文件：

```text
docs/evaluation/gold_benchmark.json
```

该文件包含 10 个典型查询，覆盖：

- 多城市：上海、苏州、成都、杭州、北京、广州、深圳、郑州。
- 多主题：充电桩、服务器、医疗设备、空调、电梯、网络设备、消防设备。
- 同义表述：充电设施、新能源充电站、信创服务器等。

`gold_notices` 默认为空，必须由人工打开源站核验后填写。禁止用系统自身结果自动回填金标。

## 2. 生成候选包

```powershell
python -m tendertrace gold-candidates --max-pages 2 --max-results 30 --out docs/evaluation/gold_candidates_latest.json
```

该命令只生成候选标注包，不修改金标文件。

## 3. 跑真实 Recall@K

```powershell
python -m tendertrace evaluate-gold --out docs/evaluation/recall_after_p23.json
```

如果 `gold_notices` 仍为空，命令返回待标注状态，Agent 评测页继续显示 `recall_proxy`。只要金标中有人工标注公告，评测页会展示：

- `Recall@5`
- `Recall@10`
- `Precision@10`
- 已标注金标用例数

## 4. 采集订阅

采集订阅与用户报告订阅分开。采集订阅只负责后台采集入库，不生成 Word，不写 `sent_history`。

```powershell
python -m tendertrace create-ingest-subscription --name 上海充电桩采集 --topic 充电桩 --region 上海 --cron "0 */6 * * *"
python -m tendertrace list-ingest-subscriptions
python -m tendertrace run-ingest-subscription <ingest_subscription_id>
```

Web 服务启动调度器时，会注册 active 的采集订阅 job，job id 形如：

```text
ingest_subscription:<id>
```

## 5. 可选向量检索

默认关闭：

```env
TENDERTRACE_VECTOR_ENABLED=false
```

启用前安装可选依赖：

```powershell
python -m pip install -e .[vector]
```

然后配置：

```env
TENDERTRACE_VECTOR_ENABLED=true
TENDERTRACE_VECTOR_MODEL=BAAI/bge-small-zh-v1.5
TENDERTRACE_VECTOR_TOP_K=30
```

生成本地公告向量：

```powershell
python -m tendertrace embed-notices
```

启用后，本地检索会执行 FTS + 向量双路召回，并使用 RRF 融合排序。未安装 `sentence-transformers` 时，系统会返回 `vector_status=unavailable`，不会假装执行了向量检索。
