# P3 公开源采集与首份报告

## 目标

P3 打通第一条真实采集闭环：自然语言问题 -> BidQL -> 中国政府采购网公开公告源 -> 详情页正文/附件抽取 -> Word 报告 -> 本地 outbox -> 运行台账和事件追踪。

本阶段只接入第一个公开源，不处理登录站、跨源去重和定时增量。登录站和 `sent_history` 增量过滤会在后续阶段接入。

## 新增模块

- `tendertrace/adapters/ccgp.py`：中国政府采购网公开招标公告适配器。
- `tendertrace/report/naming.py`：按赛题规则生成 Word 文件名。
- `tendertrace/report/docx_writer.py`：生成汇总 Word 报告。
- `tendertrace/runlog.py`：登记 `runs` 和 `outbox_messages`，让 UI 可以按 run_id 追踪。
- `tendertrace/cli.py`：新增 `run-once` 命令。
- `tendertrace/app/api.py`：`/api/outbox` 返回可下载文件，并带上 `run_id`。

## 命令

运行一次公开源采集：

```powershell
python -m tendertrace run-once "最近36个月的上海区域内的设备招标信息都有哪些" --now "2026-07-06T10:00:00+08:00" --max-pages 2 --max-results 3
```

## 报告字段

Word 报告必须包含：

- 标题
- 发布时间
- 来源链接
- 核心内容
- 附件链接，如无附件则写 `无`

报告还包含执行摘要、结果总览表、逐条详情和附录。核心内容来自详情页正文抽取，不做生成式改写。

## 可追踪性

一次 `run-once` 会写入：

- `runs`：运行状态、查询原文、时间窗口、输出路径、统计信息。
- `run_checkpoints`：`intent -> collect -> report` 三个节点检查点。
- `trace_events`：节点开始、工具调用、节点结束、运行结束等事件。
- `outbox_messages`：outbox 文件和 `run_id` 的对应关系。

API：

```http
GET http://127.0.0.1:8000/api/outbox
GET http://127.0.0.1:8000/api/traces/{run_id}
GET http://127.0.0.1:8000/api/checkpoints/{run_id}
```

`/api/outbox` 返回的每一项都带 `download_url`。已登记的文件还会带 `run_id`，便于 UI 跳转到追踪详情。

## 已知边界

- 当前仅接入中国政府采购网公开招标公告源。
- 当前报告按来源 URL 去重，尚未做跨源实体归并。
- 当前 `run-once` 是全量报告；定时增量报告会在接入订阅调度后通过 `sent_history` 控制不重复推送。
- Windows PowerShell 默认控制台可能把中文输出显示成乱码，但文件内容和测试对象为 UTF-8。
