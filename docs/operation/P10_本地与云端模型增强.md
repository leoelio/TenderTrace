# P10 本地与云端模型增强

## 阶段目标

P10 在规则意图解析基础上增加可开关的模型增强层：

- 支持本地模型模式：Ollama。
- 支持云端模型模式：OpenAI 兼容 API。
- 模型只做保守增强，不替代规则解析。
- 模型建议只追加 `topic.expanded` 和 `topic.negative`。
- 模型失败、关闭或未配置时，主抓取流程继续执行。
- 每次模型调用写入 `model_audits`，只保存状态、耗时和哈希，不保存原始 prompt、响应正文或密钥。
- Web UI、API、CLI 均可查看脱敏模型状态。

## 成功标准

1. `llm.intent_enhancer` 事件出现在运行 trace 中。
2. `model_audits` 表出现本次运行的模型审计记录。
3. 默认配置下模型增强为关闭状态，不访问 Ollama 或 OpenAI。
4. 本地模式启用后，请求 Ollama `/api/chat` 且要求 JSON 输出。
5. 云端模式启用后，请求 OpenAI `/v1/responses`，并设置 `store=false`。
6. 模型失败时仍能生成 Word、写入 outbox、记录失败审计。
7. `/api/model` 和 `tendertrace model-status` 不输出任何 API key。

## 核心文件

- `tendertrace/llm/gateway.py`：本地/云端模型网关。
- `tendertrace/llm/enhancer.py`：BidQL 模型增强器。
- `tendertrace/llm/audit.py`：模型调用审计落库。
- `tendertrace/runner.py`：在 `intent` 节点接入模型增强。
- `tendertrace/db.py`：新增 `model_audits` 表。
- `tendertrace/app/api.py`：新增 `/api/model`。
- `tendertrace/cli.py`：新增 `model-status`。
- `web/dist/index.html`、`web/dist/app.js`、`web/dist/styles.css`：Web 展示模型状态。
- `tests/test_llm_gateway.py`、`tests/test_llm_enhancer.py`：模型网关与增强器测试。

## 执行顺序

P10 后的意图节点顺序：

```text
compile_intent(query)
  -> intent.rule_parser trace
  -> ModelGateway.generate_json(...)
  -> enhance_bidql_with_model(...)
  -> model_audits insert
  -> llm.intent_enhancer trace
  -> collect
```

模型增强发生在采集前，因为采集适配器会使用 `topic.core` 和 `topic.expanded` 生成搜索词。

## 配置方式

`.env.example` 中的模型配置：

```env
TENDERTRACE_MODEL_MODE=local
TENDERTRACE_MODEL_ENHANCEMENT_ENABLED=false
TENDERTRACE_MODEL_REQUEST_TIMEOUT=8

TENDERTRACE_OLLAMA_BASE_URL=http://127.0.0.1:11434
TENDERTRACE_OLLAMA_MODEL=qwen3:8b

OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-5.5
TENDERTRACE_OPENAI_API_STYLE=responses
```

### 本地模式

1. 安装并启动 Ollama。
2. 拉取推荐本地模型：

```powershell
ollama run qwen3:8b
```

3. 在 `.env.local` 中启用：

```env
TENDERTRACE_MODEL_MODE=local
TENDERTRACE_MODEL_ENHANCEMENT_ENABLED=true
TENDERTRACE_OLLAMA_MODEL=qwen3:8b
```

### 云端模式

只把 key 放在 OS 环境变量或 `.env.local`，不要写入代码：

```env
TENDERTRACE_MODEL_MODE=cloud
TENDERTRACE_MODEL_ENHANCEMENT_ENABLED=true
OPENAI_API_KEY=your-key-here
OPENAI_MODEL=gpt-5.5
TENDERTRACE_OPENAI_API_STYLE=responses
```

默认使用 OpenAI Responses API。若需要兼容旧接口，可以改为：

```env
TENDERTRACE_OPENAI_API_STYLE=chat_completions
```

## 模型输出格式

模型必须返回严格 JSON：

```json
{
  "expanded_keywords": [],
  "negative_keywords": [],
  "intent_summary": "",
  "confidence": 0.0
}
```

系统只采纳：

- `expanded_keywords`：追加到 `topic.expanded`，来源标记为 `model`。
- `negative_keywords`：追加到 `topic.negative`。

系统不会采纳模型对地区、时间、调度、发送渠道、核心关键词的改写。

## API 与 CLI 验证

查看脱敏模型状态：

```powershell
python -m tendertrace model-status
```

返回示例：

```json
{
  "mode": "local",
  "provider": "ollama",
  "model": "qwen3:8b",
  "configured": true,
  "enhancement_enabled": false
}
```

Web API：

```powershell
curl http://127.0.0.1:8000/api/model
```

Web 工作台会显示：

- mode
- provider
- model
- configured
- enhancement enabled / disabled

## 审计表

`model_audits` 保存：

- `run_id`
- `mode`
- `provider`
- `model`
- `status`
- `latency_ms`
- `error`
- `prompt_sha256`
- `response_sha256`

不保存：

- API key
- 原始 prompt
- 原始模型响应正文

## 验收观察点

运行任务后检查：

- Trace 是否包含 `llm.intent_enhancer`。
- `model_audits` 是否有对应 `run_id`。
- `runs.stats_json` 与 Word 输出是否仍然正常。
- 模型失败时是否仍能写出 Word。
- `python -m tendertrace config-check` 是否只输出 `openai_key_configured`，不输出 key。
- Web 工作台是否显示 Model 面板。

## 当前限制

- 默认不启用模型增强，避免未安装 Ollama 时拖慢主流程。
- 模型增强只做关键词扩展和排除词建议，不做深度推理改写。
- 云端 live 调用依赖本机环境变量中的 `OPENAI_API_KEY`。
- 不在代码、测试、文档中保存真实 API key。
