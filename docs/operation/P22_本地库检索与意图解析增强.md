# P22 本地库检索与意图解析增强

本阶段把查询链路从“用户问一次，现场抓几页”改成“先采集入库，后本地检索”。目标是降低实时查询延迟，并让历史采集结果持续参与召回。

## 核心变化

1. `notices` 表继续作为公告事实表，新增字段保存采购人、核心内容和附件 JSON。
2. `notices_fts` 使用 SQLite FTS5 建全文索引，索引内容为 `title + content_text`，入索引前使用 jieba 搜索分词。
3. `run_once` 优先查询本地 FTS。若本地未发送结果足够，则直接进入清洗、证据和 Word 生成；若不足，再调用多源采集器补充。
4. 新增 `ingest-once` 和调度器 ingest job，用于按主题池、地区池后台采集并入库。
5. 意图解析改为完整省市区三级字典、采购品类词典优先、jieba 词性过滤兜底；低置信主题会通过 Web 端反问确认。

## 配置项

`.env.local` 可按需开启后台 ingest：

```env
TENDERTRACE_INGEST_ENABLED=true
TENDERTRACE_INGEST_CRON=0 */6 * * *
TENDERTRACE_INGEST_TOPICS=服务器,充电桩,空调,储能,医疗设备
TENDERTRACE_INGEST_REGIONS=北京,上海,广东,江苏,浙江
```

默认关闭后台 ingest，避免开发环境启动 Web 后自动联网采集。

## 手动入库

```powershell
python -m tendertrace ingest-once --topic 充电桩 --region 上海 --window-days 30 --max-pages 1 --max-results 20
```

该命令只采集并写入 SQLite，不生成 Word 报告。

## 本地检索验证

先执行一次 ingest，再执行同主题查询：

```powershell
python -m tendertrace run-once "最近1个月上海充电桩招标信息都有哪些" --max-pages 1 --max-results 5
```

检查运行统计中的 `local_retrieved`、`retrieval_engine` 和 Agent 评测页里的 `FTS 覆盖率`、`本地复用率`。

## 增量推送约束

订阅运行时，本地 FTS 召回到的旧公告仍会经过 `sent_history` 过滤。已经推送过的公告不会因为本地库复用而再次写入当次 Word。
