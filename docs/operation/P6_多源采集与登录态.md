# P6 多源采集与登录态

## 目标

P6 补齐赛题中的两个关键来源要求：

- 招投标信息来源至少 2 个。
- 至少选择 1 个需要登录后获取信息的网站，并使用免费会员可见范围。

本阶段默认启用两个公开 HTTP 来源：中国政府采购网 `ccgp`、全国公共资源交易平台 `ggzy`。同时新增千里马 `qianlima` 登录态管理能力：系统通过 Playwright 人工登录一次后保存 `storage_state` 到本地 `secrets/`，代码中不保存账号、密码或 Cookie 明文常量。

## 新增模块

- `tendertrace/adapters/ggzy.py`：全国公共资源交易平台适配器，使用页面真实 POST 接口 `/information/pubTradingInfo/getTradList`。
- `tendertrace/adapters/multi.py`：多源聚合器，默认合并 `ccgp` 与 `ggzy`，并在千里马登录态存在时启用 `qianlima`。
- `tendertrace/vault/qianlima.py`：千里马 Playwright `storage_state` vault、登录命令支撑和登录态页面采集雏形。
- `tendertrace/runner.py`：默认采集器由单源切换为多源，并写入 `source_stats`、`source_sites`。
- `tendertrace/app/api.py`：新增 `/api/sources`。
- `web/dist/*`：新增来源状态面板。

## 千里马登录态保存

运行：

```powershell
python -m tendertrace login-qianlima
```

操作步骤：

1. 命令会打开一个可见 Chromium 浏览器。
2. 在浏览器中手动完成千里马免费会员登录。
3. 回到终端按 Enter。
4. 系统把 Playwright `storage_state` 保存到 `secrets/qianlima_storage_state.json`。

安全约束：

- 代码不保存账号密码。
- `secrets/` 已在 `.gitignore` 中忽略。
- `source-status` 只显示路径、大小、修改时间和是否存在，不打印 Cookie 内容。

登录后再次运行：

```powershell
python -m tendertrace source-status
```

若 `qianlima.status = configured`，说明本地登录态可被后续 Playwright 采集器复用。

## GGZY 适配器说明

全国公共资源交易平台页面实际调用：

```text
POST https://www.ggzy.gov.cn/information/pubTradingInfo/getTradList
```

适配器会从 BidQL 生成表单参数：

- `FINDTXT`：主题关键词。
- `DEAL_PROVINCE`：省级行政区划码。
- `TIMEBEGIN` / `TIMEEND`：解析后的时间窗口。
- `PAGENUMBER`：页码。
- `SOURCE_TYPE=1`：交易公告来源。

如果接口返回验证码状态码 `829`，适配器会抛出明确错误，多源聚合器会记录该来源失败并继续执行其他来源。

## 已知边界

- 千里马登录需要用户手动完成；当前环境没有账号登录态，因此不能证明千里马会员内容已进入最终报告。
- `qianlima` 适配器目前是登录态采集雏形，能复用 `storage_state` 打开登录态页面并抽取候选链接；后续需要在实际免费会员页面上冻结稳定选择器。
- 多源去重当前按 `cluster_key`、站点和公告 ID 做轻量去重；跨站同项目实体归并将在后续 dedup 阶段增强。
- GGZY 可能在高频请求或复杂查询下触发验证码，当前策略是记录来源失败并保留其他来源结果。
