# P14 本地模型自检与云端隔离

## 阶段目标

P14 解决一个实际交付问题：云端模型已经配置好时，缺少本地 Ollama 配置是否会影响运行。

结论是：不会。只要 `.env.local` 中使用 `TENDERTRACE_MODEL_MODE=cloud`，系统不会依赖 Ollama；本地模型只在 `TENDERTRACE_MODEL_MODE=local` 且启用模型增强后才会被调用。

本阶段新增：

- `python -m tendertrace model-doctor`：脱敏配置自检，不发起模型请求。
- `python -m tendertrace model-doctor --live`：对当前配置的模型发起一次安全 JSON 探测。
- `GET /api/model/doctor`：Web 工作台使用的模型自检 API。
- Web Model 面板的 Doctor 按钮和自检结果区域。

## 成功标准

1. cloud 模式下 `model-doctor` 明确显示 Ollama 不必配置。
2. local 模式下 `--live` 会调用 Ollama `/api/chat` 并要求 JSON。
3. 模型探测失败时，错误信息不泄露 OpenAI key。
4. Web API 和 UI 可以查看自检结果。
5. 全量测试和 Ruff 通过。

## 使用方式

只检查配置，不联网：

```powershell
python -m tendertrace model-doctor
```

对当前模型做 live 探测：

```powershell
python -m tendertrace model-doctor --live
```

注意：`--live` 会调用当前配置的模型。cloud 模式会消耗云端接口调用；local 模式要求 Ollama 服务和模型已可用。

## 当前云端配置判断

当前工作区的 `model-status` 显示：

```text
mode=cloud
provider=openai
model=gpt-5.5
configured=true
enhancement_enabled=true
```

因此缺少本地 Ollama 不会影响当前 cloud 模式运行。

## 验证命令

```powershell
python -m unittest tests.test_llm_doctor tests.test_api_sources tests.test_web_static -v
python -m tendertrace model-doctor
python -m tendertrace model-status
python -m unittest discover -s tests -v
python -m ruff check .
```

## 安全边界

- `model-doctor` 不输出 `.env.local` 内容。
- API key 只以是否配置的布尔状态出现。
- live 探测失败时，错误摘要会脱敏 `Bearer ...` 或 `sk-...`。
- Web UI 默认调用非 live 自检，不会自动消耗云端额度。
