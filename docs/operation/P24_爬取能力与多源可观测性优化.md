# P24 爬取能力与多源可观测性优化

## 目标

本阶段参考 Scrapling 的稳健抓取思路和 Firecrawl 的结构化采集思路，补齐 TenderTrace 在比赛场景中的几个短板：

- 详情页抓取从串行改为批量执行。
- 登录态源千里马从候选页推进到详情页字段抽取。
- 多源采集过程可在 Word 和 Web 中解释。
- 结构化字段不仅给值，也给证据片段。
- URL 发现规则从适配器内部逻辑提升为可展示的 Source Map。
- 订阅增量提供一条可重复演示的 CLI 命令。

## 改动范围

### 托管抓取

`tendertrace/fetching.py` 新增线程安全统计和 `batch_get()`：

- 保持输入 URL 顺序返回详情结果。
- 统计请求、成功、失败、阻断、重试、浏览器兜底和平均耗时。
- 单个 URL 失败不会阻断同批其他详情页。

CCGP 与 GGZY 适配器使用 `batch_get()` 批量抓取详情页。GGZY 的两段式详情页也分为列表详情页和正文页两批请求。

### 登录源详情闭环

`tendertrace/vault/qianlima.py` 增强 Playwright 登录态采集：

- 搜索页解析候选公告。
- 进入详情页抽取标题、发布时间、地区、采购人、正文和附件链接。
- 使用正文选择器记录 `content_selector`、`content_fallback` 和页面快照。
- 登录页或受限页会记录 blocked/error，公开源不受影响。

### URL Map 与发现规则

`tendertrace/linking.py` 提供 `LinkExtractor`：

- 支持 allow/deny 正则。
- 支持同域限制。
- 自动识别附件扩展名。
- 去除跟踪参数后去重。

`/api/source-map` 和 `/api/sources` 会返回每个来源的入口路由与发现规则。

### Word 报告增强

`tendertrace/report/docx_writer.py` 新增：

- 运行漏斗：候选、本地复用、外部来源新增、去重后数量。
- 订阅增量说明：已跳过历史推送数量。
- 来源覆盖与抓取健康表：来源、状态、命中、请求、成功、阻断、重试、说明。
- 字段级证据：项目编号、预算金额、投标截止、开标时间对应的证据片段。

### Web 来源健康

数据源页新增：

- 近次运行。
- 累计命中。
- 成功率。
- 阻断。
- 重试。
- 页面快照数。
- 入口路由摘要。
- 发现规则摘要。

### 增量演示命令

新增命令：

```powershell
python -m tendertrace demo-incremental "最近3个月上海充电桩招标信息有哪些，请每天9:00发送给我" --max-pages 1 --max-results 5
```

输出包含：

- subscription：创建的订阅。
- first_run：第一次增量运行。
- second_run：第二次增量运行。
- incremental：两次命中数、第二次跳过数量、是否只保留新增内容。

- 不做验证码绕过，不保存千里马账号密码。
