# P13 交付收口与完成度审计

## 阶段目标

P13 把项目状态整理成最终交付视角：

- 生成 `docs/delivery/交付清单.md`。
- 生成 `docs/delivery/完成度审计.md`。
- 明确赛题要求与当前证据的对应关系。
- 明确未完全闭合的人工动作。
- 更新 README 和测试，确保交付清单不会缺失。

## 成功标准

1. 交付清单存在，覆盖四类交付物和代码/文档入口。
2. 完成度审计存在，逐项映射赛题要求。
3. 未完成项不被隐藏，明确列出 Demo 视频待录制和千里马登录态待保存。
4. `acceptance-check` 仍然通过，且 fail 为 0。
5. 单元测试、Ruff、敏感串扫描通过。

## 当前判断

代码、文档、Word/outbox、云端模型、验收 Harness 均已闭合。

剩余人工动作：

- 录制 Demo 视频。
- 若评审需要登录站实时结果，执行千里马免费会员登录态保存。

## 验证命令

```powershell
python -m tendertrace acceptance-check
python -m unittest discover -s tests -v
python -m ruff check .
```

## 注意事项

P13 不把 warning 强行改成 pass。千里马登录态缺失是外部人工登录状态，应该在审计报告中透明列出。
