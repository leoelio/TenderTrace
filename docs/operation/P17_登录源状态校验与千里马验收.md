# P17 登录源状态校验与千里马验收

## 目标

P17 面向赛题中的“至少一个登录后才能获取信息的网站”要求。P6 已经实现千里马登录态保存和 Playwright 采集入口，但此前状态判断只看 `storage_state` 文件是否存在。这个判断太弱：空文件、坏 JSON、非千里马域名 Cookie 都可能被误判为已配置。

本阶段新增结构化校验，让登录源状态可以被 CLI、API、Web UI、Demo 证据包和交付审计共同验证。

## 新增能力

### 1. storage_state 结构校验

文件：`tendertrace/vault/qianlima.py`

校验项：

- 文件是否存在。
- 文件是否为空。
- 是否为合法 JSON。
- 是否符合 Playwright `storage_state` 结构，即包含 `cookies` 和 `origins` 列表。
- 是否包含 `qianlima.com` 域名相关 Cookie 或 origin。

输出只包含计数和状态，不输出 Cookie 名称、Cookie 值、账号或密码。

### 2. CLI 校验命令

离线校验：

```powershell
python -m tendertrace verify-qianlima
```

可选 live 校验：

```powershell
python -m tendertrace verify-qianlima --live
```

`--live` 会使用已保存的 Playwright `storage_state` 以 headless 方式访问千里马搜索页，并尝试解析候选公告链接。该命令用于提交前人工确认，不纳入普通自动验收，避免外部站点波动影响本地回归。

### 3. 来源状态细化

`source-status` 和 `/api/sources` 现在会返回：

- `validation`：例如 `missing`、`empty_state`、`invalid_json`、`domain_missing`、`ready`。
- `detail`：人类可读原因。
- `ready`：是否可用于登录态采集。
- `cookie_count`、`origin_count`、`qianlima_cookie_count`、`qianlima_origin_count`。

Web UI 的来源面板会展示这些字段，方便录屏时证明登录站状态可追踪。

## 当前状态

当前本机已经保存千里马免费会员登录态，并已复制到项目本地 `secrets/qianlima_storage_state.json`。结构化校验结果为：

```text
validation: ready
ready: true
status: configured
```

live 校验已使用该登录态加载千里马搜索页，并解析到候选公告链接。若后续登录态过期，再重新执行一次人工登录即可：

```powershell
python -m tendertrace login-qianlima
python -m tendertrace verify-qianlima
python -m tendertrace verify-qianlima --live
```

## 验收方式

代码回归：

```powershell
python -m unittest tests.test_qianlima_vault tests.test_api_sources tests.test_acceptance -v
python -m ruff check tendertrace/vault/qianlima.py tendertrace/cli.py tendertrace/acceptance.py tendertrace/demo_check.py
```

全量回归：

```powershell
python -m tendertrace acceptance-check
python -m tendertrace demo-check --out docs/demo/demo_evidence_latest.json
python -m unittest discover -s tests -v
python -m ruff check .
```

## 安全边界

- 不在代码、配置、测试或文档中保存账号密码。
- 不打印 Cookie 值。
- 不把 `secrets/qianlima_storage_state.json` 纳入交付文档或敏感扫描白名单。
- 登录态是否有效由用户本机人工登录产生，系统只保存 Playwright `storage_state`。
