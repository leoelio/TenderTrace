# P1 状态图与事件流

## 目标

P1 验证 TenderTrace 的运行时骨架：一个查询任务可以被拆成多个节点执行，每个节点执行前后产生事件，每个成功节点生成检查点，失败后可以从最近检查点继续。

本阶段仍不做真实招投标抓取。

## 新增命令

```powershell
.\\.venv\\Scripts\\python -m tendertrace graph-smoke
```

成功输出应包含：

- `status: "finished"`
- `checkpoint_nodes: ["intent", "plan_sources", "report"]`
- `event_types` 中包含 `node_started`、`tool_called`、`node_finished`、`run_finished`

## 新增 API

启动服务：

```powershell
.\\.venv\\Scripts\\python -m tendertrace serve
```

查看某次运行的事件：

```text
GET http://127.0.0.1:8000/api/traces/{run_id}
```

查看某次运行的检查点：

```text
GET http://127.0.0.1:8000/api/checkpoints/{run_id}
```

`run_id` 可从 `graph-smoke` 输出中取得。

## P1 验收点

- 正常图：节点按顺序执行，状态最终为 `finished`。
- 条件图：`verify` 可以按质量结果路由到 `repair` 或 `report`。
- 恢复图：节点失败后再次运行 `resume=True`，从最近成功检查点之后继续。
- 事件流：所有节点开始、工具调用、节点结束、运行结束事件写入 `trace_events`。
- 检查点：每个成功节点写入 `run_checkpoints`，状态 JSON 可反序列化为 `RunState`。
