# TenderTrace 飞书连接审计与恢复方案

> 2026-09-24 更新：本报告记录的是恢复前状态。连接现已恢复，最新结果见《飞书连接恢复验收报告-20260924.md》。

审计时间：2026-09-24（Asia/Shanghai）  
审计方式：本地配置脱敏检查、SQLite 运行记录检查、TenderTrace 飞书状态接口、飞书开放 API 只读探测。未发送测试消息，未修改飞书数据。

## 1. 结论

当前飞书连接是“部分完成”，不能视为完整可用。

- **多维表格的鉴权和读取已连通**：程序成功获取到“招标机会”表，当前有 17 个字段、4 条记录。
- **多维表格结构未完成升级**：当前版本要求的字段中缺少 81 个，因此连接检查为 `warn`。现有表适合证明旧连接仍有效，但不足以承载当前版本的全部机会、任务、关系、事实核验和要求评审功能。
- **飞书消息应用未连接**：`FEISHU_ENABLED=false`，当前版本使用的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 和默认接收目标均未配置。
- **定时飞书推送没有运行**：本地存在一条“每天 9:00 发送”的有效订阅，但该订阅只选择了 Web 和本地 outbox，没有选择飞书；最后运行时间为 2026-08-06 06:54:24。
- **当前常驻服务关闭了调度器**：Windows 任务正在运行 `scripts/serve-local.cmd`，该脚本把 `TENDERTRACE_SCHEDULER_ENABLED` 强制设为 `false`，并把通道强制设为 `web,outbox`。所以即使 `.env.local` 中写着调度器开启，当前进程仍不会执行每天 9 点的订阅。
- **机器人收消息、智能体、任务、日历和回调均未完成**：长连接监听器未启动，回调令牌未配置，飞书智能体应用未配置。
- **没有飞书交付成功证据**：本地 `delivery_attempts`、`feishu_message_events`、`feishu_lead_import_runs` 都是 0 条。

负责人此前完成的是“定时订阅记录 + 旧版多维表格连接”，没有完成“定时任务 → 生成报告 → 发到你的飞书 → 留下成功记录”的端到端链路。

## 3. 最小恢复方案：先让每天 9 点真正发到飞书

这条路径不改现有多维表格，优先恢复你最关心的定时消息。

### 第一步：确认或创建飞书自建应用

1. 打开[飞书开放平台](https://open.feishu.cn/app)，查找当前多维表格所用 App ID 对应的自建应用。App ID 不要发到群里或写入文档。
2. 如果该应用由你所在租户管理，可以复用；否则新建一个企业自建应用。
3. 开启“机器人”能力。
4. 在权限管理中，为以下实际调用添加权限，并发布一个新版本，由管理员审批：
   - 发送消息：`POST /open-apis/im/v1/messages`
   - 读取机器人所在群：`GET /open-apis/im/v1/chats`
   - 读取授权成员：`GET /open-apis/contact/v3/users`
5. 把机器人加入你希望接收报告的飞书群。若要私聊发送，则确保应用可见范围包含你的账号。

飞书权限名称可能随开放平台调整。请在[飞书 API 调试台](https://open.feishu.cn/api-explorer)打开以上接口，以页面当前显示的“所需权限”为准。

### 第二步：补齐本地消息配置

在 `E:\tt\.env.local` 增加或修改以下内容，真实密钥只放本机：

```env
FEISHU_ENABLED=true
FEISHU_APP_ID=你的飞书自建应用AppID
FEISHU_APP_SECRET=你的飞书自建应用AppSecret
FEISHU_DEFAULT_RECEIVE_ID=
FEISHU_DEFAULT_RECEIVE_ID_TYPE=chat_id
```

`FEISHU_DEFAULT_RECEIVE_ID` 可以先留空。应用重启后，在 TenderTrace 的“设置 → 飞书连接中心 → 设置接收目标”中，从已读取的群聊或成员列表选择，避免手工复制错误 ID。

如果消息应用与当前多维表格使用同一个自建应用，可把现有 `TENDERTRACE_FEISHU_APP_ID` 和对应 Secret 填入 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`；是否为同一应用必须在飞书开放平台核对后再做。

### 第三步：先做只读检查，再由你发送一次测试消息

```powershell
cd E:\tt
.\scripts\feishu-audit.cmd
.\.venv\Scripts\python.exe -m tendertrace feishu-list-chats --page-size 20
```

预期结果：`feishu-status` 中 `enabled=true`、`configured=true`，并能列出机器人所在群。

然后打开 `http://127.0.0.1:8000`，进入“设置 → 飞书连接中心”：

1. 点击“设置接收目标”并保存。
2. 点击“发送测试消息”。
3. 刷新状态，确认最近投递为 `sent`。

### 第四步：让常驻服务真正运行调度器

当前 `E:\tt\scripts\serve-local.cmd` 是演示安全模式，明确关闭了调度器。完成测试消息后，需要把常驻服务切换为业务运行模式：

```cmd
set "TENDERTRACE_SCHEDULER_ENABLED=true"
set "TENDERTRACE_DELIVERY_CHANNELS=web,outbox,feishu_bitable"
```

也可以删除这两个 `set`，让服务读取 `.env.local`。修改后运行：

```powershell
cd E:\tt
.\scripts\stop-local.cmd
.\scripts\start-local.cmd
```

重启后检查 `/api/health`，并确认“设置 → 飞书连接中心”仍显示已连接。

### 第五步：重建带飞书通道的 9 点订阅

旧订阅本身固定为 `web,outbox`，只打开全局飞书配置不会自动改变它。最稳妥的方式是在 Web 首页重新提交原查询，勾选“同时发送飞书”，生成新订阅；确认新订阅的交付方式为“Web + 飞书”后，再删除旧订阅，避免每天执行两次。

原查询为：

```text
最近3个月上海服务器招标信息都有哪些，请汇总后每天9:00发送给我
```

验收标准：新订阅显示 `cron=0 9 * * *`、时区 `Asia/Shanghai`、投递通道包含 `feishu`；手动执行一次后飞书收到 Word 报告，`delivery_attempts` 出现 `sent` 记录。

## 4. 完整功能方案：多维表格、机器人、任务和日历

### 4.1 多维表格

现有表只有 17 个字段，而当前版本缺 81 个字段。直接在业务表补齐会大幅改变表结构，建议先复制现有表或新建 `TenderTrace机会台账` 专用表，然后把新表的 App Token 和 Table ID 写入 `.env.local`。

先只读检查：

```powershell
.\.venv\Scripts\python.exe -m tendertrace feishu-bitable-check
```

确认是专用表且已备份后，再创建缺失字段：

```powershell
.\.venv\Scripts\python.exe -m tendertrace feishu-bitable-check --ensure-fields
```

完成标准：检查结果为 `ok`，`missing_fields=[]`。如需自动导入伙伴提交的线索，再设置：

```env
TENDERTRACE_FEISHU_LEAD_IMPORT_ENABLED=true
TENDERTRACE_FEISHU_LEAD_IMPORT_CRON=*/15 * * * *
```

首次先预演：

```powershell
.\.venv\Scripts\python.exe -m tendertrace feishu-import-leads --dry-run
```

### 4.2 机器人接收自然语言命令

本机部署优先使用长连接，不需要公网回调地址。为应用添加消息接收事件和相应权限、发布版本后，单独运行：

```powershell
cd E:\tt
$env:TENDERTRACE_SCHEDULER_ENABLED = "false"
.\.venv\Scripts\python.exe -m tendertrace feishu-bot-listen
```

监听器必须常驻。Web 服务负责订阅调度，监听器自身关闭调度器，防止同一订阅执行两次。完成标准是连接中心显示“长连接运行中”，并且 `feishu_message_events` 出现收到的消息事件。

### 4.3 Task v2、成员、日历和交互卡片

在同一个自建应用中按需加入以下接口族的读写权限并重新发布：

- Task v2：创建、读取、更新任务，用于机会行动、要求任务和状态回写。
- 通讯录：读取应用可见范围内的成员基础信息，用于负责人和任务关注人绑定。
- Calendar v4：读取日历并创建/更新日程；把目标日历 ID 填入 `FEISHU_CALENDAR_ID`。
- 消息卡片与事件：用于卡片按钮回调和群内协作命令。若采用 HTTP 回调，配置 `FEISHU_CALLBACK_VERIFICATION_TOKEN` 和公网 HTTPS 地址；本地使用时可优先采用长连接。

任务自动同步需要：

```env
TENDERTRACE_FEISHU_TASK_SYNC_ENABLED=true
TENDERTRACE_FEISHU_TASK_SYNC_CRON=*/10 * * * *
```

独立智能体服务使用另一组配置：

```env
FEISHU_AGENT_ENABLED=true
FEISHU_AGENT_APP_ID=智能体应用AppID
FEISHU_AGENT_APP_SECRET=智能体应用AppSecret
```

它不是定时报告、机器人或多维表格的必要条件；没有明确业务需要时可以暂不启用。

## 5. 最终验收清单

按以下顺序验收，每项都要有可观察结果：

1. `feishu-status`：`enabled=true`、`configured=true`。
2. `feishu-list-chats`：能列出目标群；连接中心已保存默认接收目标。
3. 手工测试消息：飞书实际收到，TenderTrace 最近投递记录为 `sent`。
4. 新 9 点订阅：投递通道包含 `feishu`，手动触发一次可收到 Word 报告。
5. 调度器：常驻服务有效配置为 `scheduler_enabled=true`，次日 9 点产生新运行记录。
6. 多维表格：专用表检查为 `ok`，测试运行后新增或更新记录且不覆盖人工状态。
7. 机器人：长连接显示运行中，飞书命令产生消息事件。
8. Task/日历：测试机会能创建任务和截止日程，并可读取状态。
