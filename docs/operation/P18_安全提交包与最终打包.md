# P18 安全提交包与最终打包

## 目标

P18 把当前工作区整理成可提交的比赛交付包。前面阶段已经有代码、Web UI、设计文档、操作文档、教学 Word、Word 运行产物、Demo 视频和证据包；本阶段解决最后一个工程问题：提交时不能依赖 Git 是否追踪某个文件，也不能误带 `.env.local`、`secrets/`、数据库、缓存或登录态。

## 新增命令

```powershell
python -m tendertrace package-submission
```

命令会在 `dist/` 下生成：

- `TenderTrace_submission_YYYYMMDDHHMM.zip`
- `TenderTrace_submission_YYYYMMDDHHMM.manifest.json`

zip 内也包含一份 `SUBMISSION_MANIFEST.json`，用于复核文件列表、大小和 SHA256。

## 打包策略

采用显式白名单：

- 根文件：`README.md`、`.env.example`、`.gitignore`、`pyproject.toml`、实施计划文档。
- 源码：`tendertrace/`。
- 测试：`tests/`。
- 文档：`docs/`。
- 静态 Web：`web/dist/`。
- 运行 Word 产物：`outputs/*.docx`、`outbox/*.docx`。

采用显式黑名单：

- `.env`、`.env.local`、`.env.*`
- `secrets/`
- `data/`
- `snapshots/`
- `traces/`
- `.venv/`
- `.git/`
- 缓存目录和 Office 临时文件

注意：根目录 `dist/` 是提交包输出目录，不会被打进自己的 zip；但 `web/dist/` 是 Web UI 交付物，会被保留。

## 验收接入

`acceptance-check` 新增 `submission_package` 检查：

- `dist/TenderTrace_submission_*.zip` 必须存在且非空。
- zip 中不能出现禁止项。

因此最终提交前推荐顺序：

```powershell
python -m tendertrace package-submission
python -m tendertrace acceptance-check
python -m unittest discover -s tests -v
python -m ruff check .
```

## 当前结果

当前生成的提交包包含代码、文档、Demo 视频、证据 JSON、Web 静态文件和 Word 产物。它不包含真实 OpenAI key、不包含 `.env.local`、不包含千里马 `storage_state`、不包含 SQLite 数据库和运行快照。

## 安全边界

打包器不尝试读取 `.env.local`。它只按路径白名单收集文件，再用黑名单过滤相对路径。这样即使本机存在真实 API key 或登录态，也不会进入 zip。
