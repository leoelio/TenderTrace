# 22 本地库检索与意图解析增强

本节解释 P22 的关键代码。重点不是“多写一个搜索函数”，而是把召回瓶颈从实时网页翻页转移到本地可复用索引。

## 一、为什么要先采集入库

旧链路里，用户每查一次就现场抓取，并受 `max_pages` 限制。抓过的数据虽然写进 SQLite，但下一次查询不会复用，所以历史采集价值很低。

新链路分成两件事：

- ingest：后台按主题和地区采集，把公告写入 `notices` 与 `notices_fts`。
- query：用户查询先查本地库，缺口不足时再联网补采。

这样做后，响应速度和召回上限不再完全绑定在一次实时网页抓取上。

## 二、FTS5 索引

核心入口在 `tendertrace/retrieval.py`：

```python
def upsert_notice_fts(conn, notice_id: str, title: str, content_text: str, core_content: str) -> None:
    conn.execute("DELETE FROM notices_fts WHERE notice_id = ?", (notice_id,))
    conn.execute(
        "INSERT INTO notices_fts(notice_id, title, content_text) VALUES (?, ?, ?)",
        (notice_id, segment_for_fts(title), segment_for_fts(f"{content_text} {core_content}")),
    )
```

这里不直接把原文塞进索引，而是先用 jieba 搜索分词。原因是 SQLite FTS5 默认 tokenizer 对中文不理解，直接索引连续中文文本时，召回会很弱。

查询时使用 BM25：

```sql
SELECT n.*, bm25(notices_fts, 8.0, 1.0) AS rank
FROM notices_fts
JOIN notices n ON n.id = notices_fts.notice_id
WHERE notices_fts MATCH ?
ORDER BY rank ASC, publish_time DESC
```

`8.0, 1.0` 表示标题权重大于正文。招标公告里标题通常包含项目品类和地域，是更强的相关性信号。

## 三、Runner 如何复用本地库

`tendertrace/runner.py` 的 collect 节点先调用 `search_notices()`。如果本地未发送结果已经足够，就跳过源站采集；否则才调用适配器补充。

订阅增量尤其要小心：本地库会反复召回旧公告，所以在去重前先过滤 `sent_history`，避免同一公告因聚类 key 变化再次推送。

## 四、后台 ingest

`tendertrace/ingest.py` 的 `run_ingest_cycle()` 做主题池和地区池的笛卡尔轮询：

```python
for topic in topic_pool:
    for region in region_pool:
        bidql = compile_intent(f"最近{window_days}天{region}{topic}招标信息", now=now)
        collected = source_adapter.collect(bidql, max_pages=max_pages, max_results=max_results)
```

它复用现有多源采集器和持久化管道，不单独发明一套入库逻辑。这样清洗、聚类、FTS 写入和后续报告生成都走同一套数据结构。

## 五、行政区划解析

`tendertrace/intent/admin_divisions.py` 保存省、市、区县三级数据。`region.py` 的匹配顺序是：

1. 区县
2. 城市
3. 省级

这样用户输入“苏州”“成都”“浦东新区”都能给出明确 scope。时间短语会先从原句中剥离，避免“最近10天全国”误命中地名。

## 六、主题抽取

`topic.py` 的优先级是：

1. 采购品类词典和同义词，例如“充电设施”归一为“充电桩”。
2. jieba 词性过滤，保留名词和动名词。
3. 启发式兜底。

低置信主题不会直接带着错误关键词去检索。`compiler.py` 会把 `clarify_needed=["topic"]` 写入 BidQL，Web 端 `ensureIntentReady()` 看到后先反问用户确认。

## 七、如何验证自己没有破坏增量

看两个测试：

- `tests/test_retrieval.py`：验证“充电设施”可以被“充电桩”召回，BM25 标题命中排在正文命中前。
- `tests/test_subscriptions.py`：验证订阅第二次运行不会把已经发送过的本地库公告重复推送。

这两个测试分别守住召回能力和增量约束。
