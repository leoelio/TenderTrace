# 18 安全提交包与最终打包

这一节讲 P18 的交付打包逻辑。项目能跑是一回事，能安全提交是另一回事。最终 zip 既要包含评审需要的所有材料，又不能泄露本地密钥和登录态。

## 1. 为什么不能直接压缩整个目录

当前工作区里有几类东西不能提交：

- `.env.local`：真实 OpenAI API key 可能在里面。
- `secrets/`：千里马 Playwright `storage_state` 会在这里。
- `data/`：SQLite 运行数据库。
- `snapshots/`、`traces/`：运行快照和内部过程数据。
- `.venv/`、缓存目录：体积大，且不是源码。

如果直接右键压缩整个目录，很容易把这些内容带出去。所以 P18 做了一个显式打包器。

## 2. 白名单比黑名单更可靠

打包器首先只收集明确需要的目录：

```python
ROOT_FILES = (
    ".env.example",
    ".gitignore",
    "README.md",
    "pyproject.toml",
    "TenderTrace_implementation_plan.md",
    "TenderTrace_implementation_plan.docx",
)
```

然后再收集源码、测试、文档和 Web 静态文件：

```python
SOURCE_DIRS = (
    "tendertrace",
    "tests",
    "docs",
    "web/dist",
)
```

最后只把 `outputs/*.docx` 和 `outbox/*.docx` 作为运行产物放进去。这样既满足赛题要求的 Word 文件，又不会把整个运行目录打包进去。

## 3. 为什么 web/dist 需要特殊处理

`.gitignore` 里通常会忽略 `dist/`，因为根目录 `dist/` 是生成物。但这个项目的 `web/dist/` 是前端静态 UI，FastAPI 会直接挂载它：

```python
web_dist = settings.workspace_root / "web" / "dist"
```

所以 P18 的规则是：

- 根目录 `dist/` 不打包，因为它放提交 zip。
- `web/dist/` 要打包，因为它是 Web UI 交付物。

测试里专门覆盖了这一点，避免误删前端。

## 4. manifest 的作用

打包器会生成 `SUBMISSION_MANIFEST.json`。里面包含：

- 文件数量；
- 总字节数；
- 每个文件的相对路径；
- 每个文件的 SHA256。

这不是为了炫技，而是为了最终复核：如果提交包被改动，manifest 可以帮助定位变化。

## 5. forbidden entries 校验

`forbidden_package_entries()` 会打开 zip，检查每个 entry 的路径：

```python
return [entry for entry in entries if _is_forbidden_relative(Path(entry))]
```

如果 zip 里出现 `.env.local`、`secrets/`、`data/` 等路径，`package-submission` 会返回失败状态，`acceptance-check` 也会失败。

## 6. CLI 为什么返回 JSON

`package-submission` 输出结构化 JSON：

```json
{
  "status": "pass",
  "package_path": "...",
  "manifest_path": "...",
  "file_count": 100,
  "total_bytes": 123456,
  "forbidden_entry_count": 0
}
```

JSON 方便被脚本、CI 或后续验收工具读取。人也能直接看懂状态。

## 7. 测试如何覆盖

`tests/test_submission_package.py` 构造一个临时工作区，故意写入：

- `.env.local`
- `secrets/qianlima_storage_state.json`
- `data/tendertrace.sqlite3`

然后运行打包器，断言这些文件不在 zip 内。同时断言 `web/dist/app.js`、`outputs/report.docx`、`outbox/report.docx` 和 Demo 视频被保留。

这个测试证明打包器不是靠人工记忆，而是有可重复的安全边界。

## 8. 最终提交顺序

推荐最终顺序：

```powershell
python -m tendertrace package-submission
python -m tendertrace acceptance-check
python -m unittest discover -s tests -v
python -m ruff check .
```

如果 `source:qianlima` 仍然是 `missing`，说明本机没有执行千里马免费会员登录。这是透明 warning；要消除它，需要先运行：

```powershell
python -m tendertrace login-qianlima
python -m tendertrace verify-qianlima
```

## 9. 工程原则

提交包的目标不是“把所有东西都放进去”，而是“只放评审需要的东西”。越接近交付，越要避免手工压缩和手工筛选，因为这类动作最容易泄露密钥或漏掉关键文件。
